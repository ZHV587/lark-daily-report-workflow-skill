# 同事首次运行检查清单

## 适用场景

同事第一次在自己的 Codex 中使用 `lark-daily-report-workflow`，或当前身份、权限、团队配置不确定时，必须先执行本检查清单。检查完成前，只能生成草稿、预览和配置缺口说明，不得写入飞书。

## 硬规则

- 必须使用同事自己的 Codex 环境和自己的 `lark-cli` 登录身份。
- 不得沿用原用户的个人身份、open_id、个人 OKR、个人任务、日报历史或日报实例。
- 所有飞书读取、创建、更新、提交、回读和校验都依托 `lark-cli`。
- 必须设置用户本地偏好中的昵称。昵称为空时，必须先询问用户希望如何称呼；昵称未设置前，不得进入日报正式流程。
- 团队对话风格是团队统一配置，不由同事首次运行时单独修改。
- 未完成身份确认、权限校验和只读试运行前，不得创建或更新飞书任务、写入复盘 Base；日报正文只能生成手动填写稿，不得声称已提交。

## 检查顺序

1. 确认 `lark-cli` 可用，并完成当前同事的 `lark-cli` 登录。
2. 做身份确认：读取当前飞书用户，向用户展示姓名或可识别身份，让用户确认这是本人账号。
3. 读取 `team-config.md` 和可选的 `team-config.local.md`。确认团队对话风格存在；如果本地覆盖配置缺失、团队资源为空，必须要求先复制 `team-config.local.example.md` 并填写配置；如果 `用户本地偏好` 中昵称为空，必须询问用户希望聊天时如何称呼，并要求写入本地复制后的配置；昵称未设置前，不得进入日报正式流程。
4. 确认团队公共资源配置适用于当前同事所在团队。
5. 校验 OKR 可读：能读取当前周期、目标、KR、进度和期限。
6. 校验飞书任务可读：能读取本人今日任务、逾期任务、已完成任务和无日期但与 OKR 相关任务。
7. 校验飞书任务可写：确认具备创建或更新任务权限；未确认前只能生成任务预览。
8. 校验日报资源：能读取日报规则、字段、必选项和历史日报；若无提交接口，说明是否需要桌面端兜底。
9. 校验复盘 Base：能读取 Base、数据表、视图、字段和 `错误类型` 可用选项。
10. 生成只读试运行结果：输出日报草稿、明日任务预览、复盘 Base 预览和运行摘要，但不写入。
11. 用户确认身份、配置、权限和预览都正确后，才允许进入真实写入流程。

## 只读试运行输出

只读试运行必须展示：

- 当前飞书身份确认结果。
- 聊天昵称确认结果；昵称为空时，展示待填写提示。
- 读取到的 OKR 周期、目标/KR 概要。
- 今日飞书任务读取范围和数量。
- 上一工作日日报是否读取成功。
- 日报字段和必选项是否匹配规范。
- 复盘 Base 字段和错误类型是否可用。
- 明日计划任务化预览。
- 不写入原因：首次运行未确认前默认不写入。

## 失败处理

- `lark-cli` 未登录：停止写入，要求完成登录。
- 身份不是本人：停止写入，要求切换身份。
- 昵称为空：阻塞日报正式流程，必须询问用户希望如何称呼，并要求写入本地配置；昵称不得替代飞书身份。
- 团队配置不匹配：停止写入，输出需要更新的配置项。
- OKR 或任务不可读：只能生成部分草稿，并标注缺失数据。
- 任务、日报或 Base 不可写：不得写入对应资源，只输出预览和权限缺口。
- 用户未确认：不得写入飞书。
