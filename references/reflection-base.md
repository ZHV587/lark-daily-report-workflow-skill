# 复盘反思多维表格

## 目标配置

目标 Base、表、视图、字段 ID 和字段类型从 `references/team-config.md` 和可选的 `references/team-config.local.md` 读取；本地覆盖文件存在时以覆盖文件为准。复制给团队使用时仍需在运行时解析知识库节点并核对表、字段和类型，避免配置变化导致错写。

## 内容来源

多维表格内容只能来自最终日报的“经验复盘”。不得在多维表格中创建日报里不存在的另一套复盘。

## 拆分规则

- 一项独立复盘对应一条多维表格记录。
- 同一人员、同一日期可以写入多条记录。
- 不同问题或不同经验不要强行合并。
- 一项复盘涉及多个错误类型时允许多选，但只能选择多维表格中已有选项。
- 没有合适选项时留空，不得自行创建或臆造类型。

每条“复盘反思经验”应包含事实、根因、经验和纠正动作。

## 精确重复检查

创建前查询同一人员和日期的记录，并按以下组合比较：

`人员 + 日期 + 规范化后的复盘反思经验 + 排序后的错误类型`

文本规范化：

- 去除首尾空白。
- 连续空白压缩为一个空格。
- 不改写词义和标点含义。

组合完全相同时跳过写入，并告诉用户该记录已经同步。同日不同内容或不同错误类型仍可新增。

## 确认与校验

写入前逐条展示：

- 人员。
- 日期。
- 复盘反思经验。
- 错误类型。
- 是否检测到重复。

只有用户明确确认后才创建非重复记录。创建后逐条读取并核对字段。不得自动覆盖或删除已有记录；修改和删除必须单独预览并确认。

## 命令边界

使用 `lark-cli base +record-search` 查询同日同人候选记录，使用 `scripts/normalize_reflection.py` 生成精确重复 key。确认后用 `lark-cli base +record-batch-create` 追加非重复记录，再用 `lark-cli base +record-get` 回读校验。

如果 Base 写入部分失败，按 `references/exception-handling.md` 的 Base 部分失败分支处理；不要覆盖、删除或重复提交已成功记录。
