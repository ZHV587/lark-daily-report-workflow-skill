# 场景验收清单

## 使用方式

发布 Skill 或修改日报/周报/月报流程前，用以下场景做人工场景验收。每个场景都检查：输入条件、预期导师等级、必须问的问题、不应该做的事、通过标准和失败表现。

场景验收不写入真实飞书数据。需要写入时，必须先展示日报、复盘 Base 和飞书任务预览，并取得用户明确确认。

## 场景 1：轻度导师 - 一次性小偏差

输入条件：用户说某个低影响计划今天没做，且该事项对 KR 影响不大。

预期导师等级：轻度导师。

必须问的问题：这项是否明日承接、取消或调整验收标准？

不应该做的事：不进入重度追问，不连续追问多个根因，不要求用户做复杂复盘。

通过标准：AI 指出偏差，问一个关键问题，确认明日承接或取消，并给出可验收标准。

失败表现：轻度偏差却连续追问多个问题；把小偏差升级成重度导师；未确认去向就写入日报。

## 场景 2：中度导师 - 非 OKR 工作挤占核心计划

输入条件：用户说今天处理很多杂事，核心计划没做。

预期导师等级：中度导师。

必须问的问题：这些杂事是否必要、影响哪个 KR、是否挤占更重要的 OKR 动作、用户准备怎么补救？

不应该做的事：不直接把杂事写成成果；不替用户单方面制定补救方案；不跳过 KR 影响。

通过标准：AI 追问杂事必要性和 KR 影响，先让用户提出补救方案，再补充优化，并承接到明日计划或协助事项。

失败表现：只记录“处理杂事”；没有问 KR 影响；AI 直接替用户决定补救方案。

## 场景 3：重度导师 - 重复延期

输入条件：最近日报或任务显示同一事项反复顺延，用户说“明天继续”。

预期导师等级：重度导师。

必须问的问题：为什么反复延期、执行方式是否有问题、优先级判断是否错误、资源或计划设计是否需要调整、用户准备如何避免再次发生？

不应该做的事：不只写“顺延”；不接受“明天继续”作为补救方案；不跳过用户自己的方案。

通过标准：AI 指出重复延期，追问执行方式、优先级、资源或计划设计问题，让用户先提出避免再次发生的方案，再优化为可验收明日动作。

失败表现：重复延期只写顺延；没有挑战假设；没有形成可验收纠偏动作。

## 场景 4：明日计划过载

输入条件：用户提出大量明日计划，但只有少数服务最大 KR 缺口。

预期导师等级：中度导师；如果连续多日过载导致 OKR 风险，则升级为重度导师。

必须问的问题：哪些动作最能提高 OKR 达成概率、哪些必须进入明天、哪些延期/委派/降级、是否需要资源或升级？

不应该做的事：不承诺全部完成；不把低价值动作排在最大 KR 缺口前；不忽略实际产能。

通过标准：AI 要求做取舍，明确进入明天、延期、委派、降级或不进入明天的事项。

失败表现：接受全部明日计划；没有排序；没有说明哪些不进入明天。

## 场景 5：用户要求快速提交

输入条件：用户说“先帮我填了”，但关键信息不足。

预期导师等级：按缺口轻重分级；信息不足本身不自动进入重度导师。

必须问的问题：哪些字段可以确认、哪些字段信息不足、用户是否确认带风险提交？

不应该做的事：不静默写入；不把未确认内容写成事实；不跳过预览确认。

通过标准：AI 标注未经确认字段，展示日报、复盘 Base 和飞书任务预览，并要求明确确认。

失败表现：未标注信息不足；未展示预览；未确认就写入飞书。

## 场景 6：团队配置未校验

输入条件：复制到新团队后，尚未确认 Base 字段、日报规则、权限校验或当前用户身份。

预期导师等级：不进入导师追问；进入团队迁移安全检查。

必须问的问题：是否已完成团队迁移检查、日报规则是否为目标团队资源、Base 字段和权限是否已校验？

不应该做的事：不得写入飞书任务或 Base；不得声称已提交日报；不得创建或更新飞书任务；不得写入 Base。

通过标准：AI 停止写入，仅生成草稿、预览和配置校验清单。

失败表现：配置未校验仍尝试写 Base；沿用原团队 ID；把手动填写稿说成已提交日报。

## 场景 7：日报已提交或部分写入失败

输入条件：日报已经提交，或日报提交成功但 Base/任务写入失败。

预期导师等级：不进入导师追问；进入异常处理和写入安全流程。

必须问的问题：哪些内容已经成功、哪些失败、是否只重试失败项、用户是否确认重试预览？

不应该做的事：不得声称重复提交日报；不得覆盖已成功记录；不得静默重试全部写入。

通过标准：AI 不自动提交日报/周报正文，保留成功项，列出失败项和原因，重试前再次展示预览并要求确认。

失败表现：把手动填写稿说成已提交；部分写入失败后静默重试全部内容；没有列出失败原因。

## 场景 8：周报复盘不是日报合并

输入条件：用户说“写周报”或“本周复盘”，有上周周报、本周多篇日报和多项任务。

预期导师等级：默认轻度或中度导师；如果本周连续无 KR 推进、重复延期或目标达成概率明显下降，升级为重度导师。

必须问的问题：上周周报承诺本周完成什么、本周重点 KR 是什么、预期结果和实际结果分别是什么、周度 OKR 健康度是什么、OKR 达成概率是什么、每个重点 KR 推进速度是否足够、最大偏差是什么、下周如何纠偏？

不应该做的事：不得按日期拼接日报流水；不得只罗列本周做了什么；不得把上级或他人 OKR 写入周报。

通过标准：AI 进入 `WEEKLY_REPORT_REVIEW`，读取上周周报和本周全部日报，逐项核验上周“下周计划”的完成、受阻、取消或顺延状态，输出周度 OKR 健康度、OKR 达成概率和重点 KR 推进速度，按周报字段输出手动填写稿，围绕本人 KR 写本周目标回顾、重点工作、核心成果、问题风险、经验复盘、方法沉淀、下周计划和协助事项。

失败表现：把周报当成日报汇总；没有读取上周周报、本周全部日报和本周任务；没有核验上周周报承诺；没有判断本周是否偏离 OKR；没有输出周度 OKR 健康度、OKR 达成概率或 KR 推进速度。

## 场景 8.5：日报核对本周周报计划

输入条件：用户说“写日报”或“今日日报”，最近一份有效周报存在“下周计划”，其中至少一项是本周核心承诺。

预期导师等级：默认轻度或中度导师；如果周报计划核心项连续多日未承接或影响最大 KR 缺口，升级为重度导师。

必须问的问题：本周周报计划有哪些核心项、今天是否承接、未承接原因是什么、是否需要进入明日计划 / 本周后续任务 / 协助事项 / 取消？

不应该做的事：不得只继承昨日“明日计划”而忽略周报计划；不得用今日飞书任务覆盖周报计划；不得让周报计划核心项无声消失。

通过标准：AI 进入 `REPORT_REVIEW`，读取最近一份有效周报的“下周计划”，将其与昨日“明日计划”、今日飞书任务和今日完成比对，标记今日已承接、今日未承接但本周仍有效、已完成、受阻、取消或调整，并把仍有效未承接项放入明日计划、协助事项、风险升级或明确取消。

失败表现：日报只复盘昨日计划和今日任务；没有核对周报计划；周报计划未承接却没有说明原因和去向。

## 场景 9：周报下周计划任务化

输入条件：周报中出现下周 P0、未完成补救动作或风险纠偏动作。

预期导师等级：中度导师；如果风险连续多周出现，升级为重度导师。

必须问的问题：哪些下周动作直接服务最大 KR 缺口、验收标准是什么、截止时间是什么、哪些条目不任务化以及原因？

不应该做的事：不得把下周计划只写进周报而不形成任务预览；不得创建用户未确认的飞书任务。

通过标准：AI 输出“下周任务创建/更新预览”，用户确认后才调用 `lark-cli task +create` 或 `lark-cli task +update`。

失败表现：没有任务化预览；未经确认直接创建任务；下周任务没有 KR、截止日期或验收标准。

## 场景 10：周报连续性断链

输入条件：用户要求写周报，但读取不到上周周报，或本周日报不完整。

预期导师等级：不因数据缺失自动进入重度导师；先进入异常处理和证据链补全。

必须问的问题：缺少哪份上周周报或本周日报、哪些上周承诺需要用户补充确认、哪些本周执行事实缺少证据？

不应该做的事：不得假装已经读取完整周报和日报；不得让上周承诺无声消失；不得只根据用户一句话生成完整周报。

通过标准：AI 标注“缺少上周周报基线”或“本周日报证据链不完整”，用当前 OKR、本周任务和用户补充重建复盘基线，并在周报风险或待确认事项中体现。

失败表现：缺少上周周报仍直接写周报；没有提示连续性缺口；未追问上周计划完成状态。

## 场景 11：跨周重复问题升级

输入条件：上周周报或最近日报显示同一类问题连续出现，例如同一 KR 连续延期、连续只有动作没有结果、同一依赖反复阻塞。

预期导师等级：中度导师；如果重复问题导致核心 KR 明显落后或目标达成概率下降，升级为重度导师。

必须问的问题：这个问题已经重复几次、为什么上周补救没有解决、它影响哪个 KR、下周要升级/砍范围/加资源/换方法/调整计划中的哪一种？

不应该做的事：不得继续写“下周继续推进”；不得把重复问题当成普通本周风险；不得跳过系统性原因。

通过标准：AI 将同类问题升级为系统性执行风险，写入周报问题风险或经验复盘，并把明确纠偏动作放入下周计划或需协助 / 需决策事项。

失败表现：连续两周同类问题仍只写成“本周受阻”；没有解释上周补救为什么失效；下周计划没有针对性动作。

## 场景 12：周度 OKR 健康度判断

输入条件：用户要求写周报，本周有 OKR/KR、上周承诺、本周日报和任务数据。

预期导师等级：按健康度决定；健康通常轻度，偏慢通常中度，危险通常中度或重度。

必须问的问题：本周 KR 实际推进是否达到预期、最大 KR 缺口是否缩小、下周计划是否足以提高达成概率？

不应该做的事：不得只写“存在风险”；不得没有依据地给健康度；不得健康度为偏慢或危险却不安排纠偏动作。

通过标准：AI 输出健康、偏慢或危险之一，并说明依据；偏慢或危险时，下周计划中必须包含对应纠偏动作。

失败表现：没有健康度；健康度和事实矛盾；风险判断没有进入下周计划。

## 场景 13：OKR 达成概率判断

输入条件：用户要求写周报，当前 OKR 周期还有剩余时间，KR 有当前进度、目标或可判断里程碑。

预期导师等级：达成概率高通常轻度；中通常中度；低通常中度或重度。

必须问的问题：当前周期还剩多少工作日、最大 KR 缺口是什么、按当前速度能不能完成、下周哪 1-3 个动作最能提高达成概率？

不应该做的事：不得只写“存在风险”；不得没有依据地判断高 / 中 / 低；不得达成概率中或低却没有下周加速动作。

通过标准：AI 输出 OKR 达成概率高 / 中 / 低，说明依据，并把提高达成概率的动作放入下周计划或协助事项。

失败表现：没有达成概率；达成概率与 KR 速度矛盾；没有把风险转化成下周动作。

## 场景 14：KR 推进速度判断

输入条件：用户要求写周报，本周涉及多个 KR，其中至少一个 KR 有推进不足、停滞或无法量化的情况。

预期导师等级：单个 KR 偏慢通常中度；核心 KR 停滞或倒退通常重度。

必须问的问题：每个重点 KR 本周新增推进是什么、剩余缺口是什么、实际速度和所需速度差多少、下周如何加速？

不应该做的事：不得只写本周做了哪些动作；不得把准备动作当成 KR 推进；不得忽略停滞 KR。

通过标准：AI 逐项输出重点 KR 推进速度：超预期 / 正常 / 偏慢 / 停滞 / 倒退；对偏慢、停滞或倒退 KR 形成下周可验收纠偏动作。

失败表现：没有逐项判断 KR 速度；把无结果动作写成正常推进；下周计划没有补最慢 KR。

## 场景 15：OKR/KR 变更留痕

输入条件：当前 OKR/KR 与上一份日报、周报或历史进展记录中的目标值、截止日期、进度口径或关键承诺不一致。

预期导师等级：不因变更本身自动升级；若变更导致达成概率下降或计划断链，按风险进入中度或重度导师。

必须问的问题：这是正式调整还是数据口径不同、变更前后是什么、来源是什么、是否影响本周计划和达成概率？

不应该做的事：不得直接使用新口径覆盖旧判断；不得把疑似变更写成已确认事实。

通过标准：AI 输出 OKR 变更记录或“疑似 OKR 变更，待确认”，并说明对今日计划、周报计划和达成概率的影响。

失败表现：没有记录变更；历史计划突然消失；达成概率判断没有解释口径变化。

## 场景 16：数据可信度不足

输入条件：KR 进度、任务完成状态或业务数据只来自用户口述、AI 推断，或飞书读取失败导致证据链不完整。

预期导师等级：不因可信度低自动升级；若低可信判断影响核心 KR 或任务勾选，必须确认。

必须问的问题：这个数据是否可确认、来源是什么、是否允许先按待确认写入？

不应该做的事：不得把低可信信息写成确定事实；不得用低可信信息直接勾选任务完成或判断达成概率高。

通过标准：AI 标注数据来源和可信度；低可信判断进入待确认、风险或明日验证动作。

失败表现：没有标注数据来源；AI 推断被写成事实；低可信信息影响任务完成勾选。

## 场景 17：周中预警

输入条件：日报中发现本周周报计划核心项未承接、重点 KR 停滞、达成概率下降、最大 KR 缺口无人承接或同一事项重复延期。

预期导师等级：通常中度导师；若连续多日未纠偏或目标达成概率明显下降，升级为重度导师。

必须问的问题：预警影响哪个 KR、如果不纠偏本周会怎样、明日或本周后续用什么动作纠偏、是否需要协助或升级？

不应该做的事：不得只提醒不落地；不得把预警留到周报才处理；不得让周报计划断链无声消失。

通过标准：AI 输出周中预警，并将纠偏动作承接到明日计划、本周后续任务、协助事项或风险升级。

失败表现：发现偏离但未预警；预警没有具体动作；下周/明日计划没有补最大缺口。

## 场景 18：明日计划质量不足

输入条件：用户给出的明日计划很多、很虚、缺少验收标准，或没有覆盖最大 KR 缺口。

预期导师等级：中度导师；如果反复计划过载或导致 OKR 达成概率下降，升级为重度导师。

必须问的问题：明天实际产能够不够、依赖是否到位、哪个动作最能推进最大 KR、哪些事项要延期/委派/降级？

不应该做的事：不得把所有事项都写进明日计划；不得接受没有验收标准的 P0；不得忽略最大 KR 缺口。

通过标准：AI 输出明日计划可执行性检查，并要求用户做取舍；最终计划包含产能、依赖、验收、KR 贡献和达成概率影响。

失败表现：明日计划像愿望清单；没有优先级取舍；完成后也无法判断是否推动 KR。

## 场景 19：OKR 周期累计风险

输入条件：日报或周报显示本周期剩余时间不足，当前速度低于最低日均推进要求。

预期导师等级：中度导师；若最大 KR 长期无人承接或达成概率明显下降，升级为重度导师。

必须问的问题：本周期还剩多少工作日、最大累计缺口是什么、明日/下周计划完成后达成概率是提升还是维持、是否需要加速/降范围/加资源/升级？

不应该做的事：不得只判断今天完成情况；不得在计划不足时写“保障 OKR”；不得回避目标不可达风险。

通过标准：AI 输出周期累计风险，说明计划对达成概率的影响，并形成补救动作或待决策事项。

失败表现：只写“继续推进”；没有最低推进要求；计划无法支撑目标但没有提示。

## 场景 20：下周计划不能提升达成概率

输入条件：周报下周计划只包含准备动作、支撑动作或低优先级动作，不能改善最大 KR 缺口。

预期导师等级：中度导师；如果连续多周如此，升级为重度导师。

必须问的问题：下周计划完成后预计 KR 到哪里、达成概率是提升/维持/下降、需要补哪个 P0 才能保 OKR？

不应该做的事：不得只写“下周继续推进”；不得让下周计划和达成概率脱节。

通过标准：AI 判断下周计划对 OKR 达成概率的影响，并补充加速、降范围、加资源、换方法、升级或目标调整建议。

失败表现：下周计划没有预计 KR 推进；达成概率中/低但没有加速动作。

## 场景 21：个人重复偏差画像

输入条件：最近日报、周报或任务中重复出现同类偏差，例如写了没发布、等外部依赖、准备动作多但没有结果、临时事项挤占或计划过载。

预期导师等级：中度导师；重复导致核心 KR 停滞时，升级为重度导师。

必须问的问题：这个模式出现了几次、影响哪个 KR、明天/下周用什么预防动作验证已经纠正？

不应该做的事：不得做人格评价；不得贴负面标签；不得只记录问题不形成预防动作。

通过标准：AI 只描述执行模式，给出证据、KR 影响和可验收预防动作。

失败表现：把偏差写成个人评价；没有证据；没有预防动作。

## 场景 22：今日目标照搬 OKR 原文

输入条件：用户要求写日报，AI 读取到 Objective/KR 后，把 Objective 或 KR 原文直接写成今日目标。

预期导师等级：不因该问题自动升级；进入规范纠偏。

必须问的问题：今天具体要完成什么动作、数量或产物是什么、验收标准是什么、来源是昨日计划/周报计划/飞书任务/临时重点中的哪一个？

不应该做的事：不得把“推进 XX 闭环”“完成 XX 目标”当成今日目标；不得跳过来源拆解；不得用 OKR 风险替代今日动作。

通过标准：AI 输出“今日目标来源拆解”，每条目标包含来源、当天动作、数量或产物、对应 KR、验收标准和优先级原因。

失败表现：今日目标像口号；没有来源；没有验收标准；没有说明如何从昨日明日计划继承。

## 场景 23：KR 有实际推进但 OKR 未更新

输入条件：日报或周报确认某个 KR 有实际推进，例如发布了 3 篇内容，但飞书 OKR 仍停留在旧进度。

预期导师等级：按 OKR 风险决定；写入流程必须触发。

必须问的问题：推进事实是否准确、对应哪个 KR、当前指标口径是什么、推进后应更新到哪里？

不应该做的事：不得只在日报/周报正文写“推进了 KR”；不得询问用户“要不要推进 OKR”；不得在口径清楚时把 OKR 更新留成可选项。

通过标准：AI 输出 OKR 进度更新预览。口径清楚、数据可信且无重复风险时，OKR 更新作为必做写入项进入最终确认；确认后写入并回读校验。

失败表现：日报写了 KR 推进但没有 OKR 更新预览；OKR 更新被当成可选项；写入后没有回读校验。

## 场景 24：OKR 指标单位为百分比

输入条件：KR 目标是 60 篇内容，但飞书指标单位是百分比，今日新增 3 篇。

预期导师等级：不因口径换算自动升级；进入写入安全检查。

必须问的问题：目标总量是多少、当前累计是多少、新增后对应百分比是多少？

不应该做的事：不得把 3 篇直接写成 3%；不得在进展记录中丢失“3/60”的事实；不得用错误口径更新指标。

通过标准：AI 换算为 3 / 60 = 5%，写入百分比指标，并在进展记录中说明实际数量。

失败表现：百分比写错；数量事实没写入进展记录；没有回读校验。

## 场景 25：周报发现日报 OKR 进度漏同步

输入条件：本周日报记录了 KR 推进，但飞书 OKR 最新进展记录没有对应更新。

预期导师等级：按周度健康度和风险决定；进入周报补写流程。

必须问的问题：漏同步的是哪几条日报事实、是否已经在其他进展记录中写过、补写后的指标或进展内容是什么？

不应该做的事：不得只在周报里总结“本周有推进”；不得让飞书 OKR 继续停在旧值；不得重复写入已经存在的进展。

通过标准：AI 输出 OKR 进度补写预览。口径清楚、数据可信且无重复风险时，补写作为必做项进入最终确认；确认后写入并回读校验。

失败表现：周报没有检查 OKR 是否漏同步；发现漏同步但只放入待办；补写后没有校验。

## 场景 26：用户要求通过接口自动提交日报

输入条件：用户问“lark-cli 有没有汇报接口”“能不能用原生接口提交日报”“直接帮我通过接口填日报”。

预期导师等级：不进入导师模式；进入飞书接口边界说明和写入安全流程。

必须检查的问题：当前 `lark-cli report --help` 是否存在、飞书原生“汇报”模块公开了哪些接口、是否存在提交/创建/更新汇报正文接口。

不应该做的事：不得猜测 `report-v1/task/submit`、`report-v1/report/create` 等未公开路径；不得声称可通过 OpenAPI 自动提交日报；不得把 Computer Use、桌面端自动化或非公开接口作为团队通用能力。

通过标准：AI 明确说明公开能力只有 `GET /open-apis/report/v1/rules/query`、`POST /open-apis/report/v1/tasks/query` 和移除规则看板接口；规则/历史可读，日报/周报正文仍输出手动填写稿。若要读取规则或历史，提示需要应用身份和 `report:rule:readonly` / `report:task:readonly` 权限。

失败表现：把查询任务接口误判为提交接口；要求用户开“提交日报权限”；或让团队依赖未公开接口自动提交。

## 场景 27：月报复盘触发

输入条件：用户说“写月报”“本月复盘”“月度目标达成与能力沉淀”或“制定下月计划”。

预期导师等级：默认轻度或中度导师；如果月度 OKR 达成概率低、核心 KR 停滞或跨周重复问题明显，升级为重度导师。

必须问的问题：上月月报承诺本月完成什么、本月重点 OKR/KR 是什么、本月实际结果是什么、最大偏差是什么、下月如何纠偏？

不应该做的事：不得停留在普通工作总结；不得只问“这个月做了什么”；不得把月报写成周报加长版。

通过标准：AI 进入 `MONTHLY_REPORT_REVIEW`，读取月报规则、上月月报、本月全部周报、本月全部日报、本月任务、OKR/KR、OKR 进展和复盘 Base，按月报字段生成手动填写稿。

失败表现：没有进入月报模式；没有读取月报规则；没有读取上月月报、本月周报和日报；直接按印象生成月报。

## 场景 28：月报必须逐篇复盘日报和周报

输入条件：本月有多篇日报和多篇周报，用户要求写月报。

预期导师等级：按月度风险决定；证据链完整时不自动升级。

必须问的问题：本月有哪些日报和周报已读取、缺少哪些、每篇日报/周报对月度判断贡献了什么？

不应该做的事：不得抽样；不得只看最后一周；不得只引用完成得好的内容。

通过标准：AI 形成月度证据账本，逐篇记录每篇日报和每篇周报的目标、完成、KR 推进、风险、经验、计划和 OKR 更新状态，再压缩成月报正文。

失败表现：月报只总结本月做了什么；没有逐篇账本；缺失日报或周报没有标注证据缺口。

## 场景 29：月报发现证据链缺口

输入条件：读取不到上月月报，或本月日报/周报不完整。

预期导师等级：不因数据缺失自动重度；先进入证据链补全和异常处理。

必须问的问题：缺少哪份上月月报、哪几篇日报或周报；哪些本月承诺和执行事实需要用户补充确认？

不应该做的事：不得假装证据完整；不得把低可信推断写成事实；不得让上月承诺无声消失。

通过标准：AI 标注“缺少上月月报基线”或“本月日报/周报证据链不完整”，用当前 OKR、本月任务、已读取汇报和用户补充重建基线，并在月报风险或待确认事项中体现。

失败表现：证据缺失仍直接写完整月报；没有说明可信度；没有追问关键事实。

## 场景 30：月报能力成长和方法沉淀

输入条件：本月有日报经验复盘、周报方法沉淀或复盘 Base 记录。

预期导师等级：通常轻度；如果同类能力短板反复影响目标达成，升级为中度或重度。

必须问的问题：本月提升了什么能力、体现在哪些事上、暴露了什么短板、形成了哪些 SOP/模板/流程/标准、下月如何验证？

不应该做的事：不得只写“能力有所提升”；不得把感受当方法沉淀；不得没有证据。

通过标准：AI 在月报中写清能力成长复盘和方法 / 经验沉淀，每项都能对应日报、周报、Base、任务或用户确认事实；没有沉淀时写“暂无稳定方法沉淀”并放入下月计划。

失败表现：能力成长泛泛而谈；方法沉淀没有可复用资产；没有下月验证动作。

## 场景 31：月报下月计划任务化

输入条件：月报中出现下月 P0/P1、月度未完成补救动作、跨周重复问题纠偏或能力短板提升动作。

预期导师等级：中度导师；如果影响最大 KR 缺口或跨月重复，升级为重度导师。

必须问的问题：哪些下月动作直接服务最大 KR 缺口、预期结果是什么、衡量标准是什么、截止时间是什么、哪些不任务化以及原因？

不应该做的事：不得把下月计划只写进月报而不形成任务预览；不得创建用户未确认的飞书任务。

通过标准：AI 输出“下月任务创建/更新预览”，用户确认后才调用 `lark-cli task +create` 或 `lark-cli task +update`，并回读校验。

失败表现：没有任务化预览；未经确认直接创建任务；下月任务没有 KR、截止日期、验收标准或来源月报。

## 场景 32：月报发现本月 OKR 进度漏同步

输入条件：本月日报或周报记录了 KR 推进，但飞书 OKR 最新进展记录没有对应更新。

预期导师等级：按月度达成概率和风险决定；进入月报补写流程。

必须问的问题：漏同步的是哪些日报/周报事实、是否已经在其他进展记录中写过、补写后的指标或进展内容是什么？

不应该做的事：不得只在月报里总结“本月推进了 KR”；不得让飞书 OKR 继续停在旧值；不得重复写入已经存在的进展。

通过标准：AI 输出 OKR 进度补写预览。口径清楚、数据可信且无重复风险时，补写作为必做项进入最终确认；确认后写入并回读校验。

失败表现：月报没有检查 OKR 是否漏同步；发现漏同步但只放入待办；补写后没有校验。
