# 场景验收清单

## 使用方式

发布 Skill 或修改日报/周报流程前，用以下场景做人工场景验收。每个场景都检查：输入条件、预期导师等级、必须问的问题、不应该做的事、通过标准和失败表现。

场景验收不写入真实飞书数据。需要写入时，必须先展示日报、复盘 Base 和飞书任务预览，并取得用户明确确认。

## 场景 1：轻度导师 - 一次性小偏差

输入条件：用户说某个低影响计划今天没做，且该事项对 KR 影响不大。

预期导师等级：轻度导师。

必须问的问题：这项是否明日承接、取消或调整验收标准？

不应该做的事：不进入重度追问，不连续追问多个根因，不要求用户做复杂复盘。

通过标准：AI 指出偏差，问一个关键问题，确认明日承接或取消，并给出可验收标准。

失败表现：轻度偏差却连续追问多个问题；把小偏差升级成重度导师；未确认去向就写入日报。

## 场景 2：中度导师 - 非 OKR 工作挤占核心计划

输入条件：用户说今天处理很多杂事，核心计划没做。

预期导师等级：中度导师。

必须问的问题：这些杂事是否必要、影响哪个 KR、是否挤占更重要的 OKR 动作、用户准备怎么补救？

不应该做的事：不直接把杂事写成成果；不替用户单方面制定补救方案；不跳过 KR 影响。

通过标准：AI 追问杂事必要性和 KR 影响，先让用户提出补救方案，再补充优化，并承接到明日计划或协助事项。

失败表现：只记录“处理杂事”；没有问 KR 影响；AI 直接替用户决定补救方案。

## 场景 3：重度导师 - 重复延期

输入条件：最近日报或任务显示同一事项反复顺延，用户说“明天继续”。

预期导师等级：重度导师。

必须问的问题：为什么反复延期、执行方式是否有问题、优先级判断是否错误、资源或计划设计是否需要调整、用户准备如何避免再次发生？

不应该做的事：不只写“顺延”；不接受“明天继续”作为补救方案；不跳过用户自己的方案。

通过标准：AI 指出重复延期，追问执行方式、优先级、资源或计划设计问题，让用户先提出避免再次发生的方案，再优化为可验收明日动作。

失败表现：重复延期只写顺延；没有挑战假设；没有形成可验收纠偏动作。

## 场景 4：明日计划过载

输入条件：用户提出大量明日计划，但只有少数服务最大 KR 缺口。

预期导师等级：中度导师；如果连续多日过载导致 OKR 风险，则升级为重度导师。

必须问的问题：哪些动作最能提高 OKR 达成概率、哪些必须进入明天、哪些延期/委派/降级、是否需要资源或升级？

不应该做的事：不承诺全部完成；不把低价值动作排在最大 KR 缺口前；不忽略实际产能。

通过标准：AI 要求做取舍，明确进入明天、延期、委派、降级或不进入明天的事项。

失败表现：接受全部明日计划；没有排序；没有说明哪些不进入明天。

## 场景 5：用户要求快速提交

输入条件：用户说“先帮我填了”，但关键信息不足。

预期导师等级：按缺口轻重分级；信息不足本身不自动进入重度导师。

必须问的问题：哪些字段可以确认、哪些字段信息不足、用户是否确认带风险提交？

不应该做的事：不静默写入；不把未确认内容写成事实；不跳过预览确认。

通过标准：AI 标注未经确认字段，展示日报、复盘 Base 和飞书任务预览，并要求明确确认。

失败表现：未标注信息不足；未展示预览；未确认就写入飞书。

## 场景 6：团队配置未校验

输入条件：复制到新团队后，尚未确认 Base 字段、日报规则、权限校验或当前用户身份。

预期导师等级：不进入导师追问；进入团队迁移安全检查。

必须问的问题：是否已完成团队迁移检查、日报规则是否为目标团队资源、Base 字段和权限是否已校验？

不应该做的事：不得写入飞书任务或 Base；不得声称已提交日报；不得创建或更新飞书任务；不得写入 Base。

通过标准：AI 停止写入，仅生成草稿、预览和配置校验清单。

失败表现：配置未校验仍尝试写 Base；沿用原团队 ID；把手动填写稿说成已提交日报。

## 场景 7：日报已提交或部分写入失败

输入条件：日报已经提交，或日报提交成功但 Base/任务写入失败。

预期导师等级：不进入导师追问；进入异常处理和写入安全流程。

必须问的问题：哪些内容已经成功、哪些失败、是否只重试失败项、用户是否确认重试预览？

不应该做的事：不得声称重复提交日报；不得覆盖已成功记录；不得静默重试全部写入。

通过标准：AI 不自动提交日报/周报正文，保留成功项，列出失败项和原因，重试前再次展示预览并要求确认。

失败表现：把手动填写稿说成已提交；部分写入失败后静默重试全部内容；没有列出失败原因。

## 场景 8：周报复盘不是日报合并

输入条件：用户说“写周报”或“本周复盘”，有上周周报、本周多篇日报和多项任务。

预期导师等级：默认轻度或中度导师；如果本周连续无 KR 推进、重复延期或目标达成概率明显下降，升级为重度导师。

必须问的问题：上周周报承诺本周完成什么、本周重点 KR 是什么、预期结果和实际结果分别是什么、周度 OKR 健康度是什么、OKR 达成概率是什么、每个重点 KR 推进速度是否足够、最大偏差是什么、下周如何纠偏？

不应该做的事：不得按日期拼接日报流水；不得只罗列本周做了什么；不得把上级或他人 OKR 写入周报。

通过标准：AI 进入 `WEEKLY_REPORT_REVIEW`，读取上周周报和本周全部日报，逐项核验上周“下周计划”的完成、受阻、取消或顺延状态，输出周度 OKR 健康度、OKR 达成概率和重点 KR 推进速度，按周报字段输出手动填写稿，围绕本人 KR 写本周目标回顾、重点工作、核心成果、问题风险、经验复盘、方法沉淀、下周计划和协助事项。

失败表现：把周报当成日报汇总；没有读取上周周报、本周全部日报和本周任务；没有核验上周周报承诺；没有判断本周是否偏离 OKR；没有输出周度 OKR 健康度、OKR 达成概率或 KR 推进速度。

## 场景 8.5：日报核对本周周报计划

输入条件：用户说“写日报”或“今日日报”，最近一份有效周报存在“下周计划”，其中至少一项是本周核心承诺。

预期导师等级：默认轻度或中度导师；如果周报计划核心项连续多日未承接或影响最大 KR 缺口，升级为重度导师。

必须问的问题：本周周报计划有哪些核心项、今天是否承接、未承接原因是什么、是否需要进入明日计划 / 本周后续任务 / 协助事项 / 取消？

不应该做的事：不得只继承昨日“明日计划”而忽略周报计划；不得用今日飞书任务覆盖周报计划；不得让周报计划核心项无声消失。

通过标准：AI 进入 `REPORT_REVIEW`，读取最近一份有效周报的“下周计划”，将其与昨日“明日计划”、今日飞书任务和今日完成比对，标记今日已承接、今日未承接但本周仍有效、已完成、受阻、取消或调整，并把仍有效未承接项放入明日计划、协助事项、风险升级或明确取消。

失败表现：日报只复盘昨日计划和今日任务；没有核对周报计划；周报计划未承接却没有说明原因和去向。

## 场景 9：周报下周计划任务化

输入条件：周报中出现下周 P0、未完成补救动作或风险纠偏动作。

预期导师等级：中度导师；如果风险连续多周出现，升级为重度导师。

必须问的问题：哪些下周动作直接服务最大 KR 缺口、验收标准是什么、截止时间是什么、哪些条目不任务化以及原因？

不应该做的事：不得把下周计划只写进周报而不形成任务预览；不得创建用户未确认的飞书任务。

通过标准：AI 输出“下周任务创建/更新预览”，用户确认后才调用 `lark-cli task +create` 或 `lark-cli task +update`。

失败表现：没有任务化预览；未经确认直接创建任务；下周任务没有 KR、截止日期或验收标准。

## 场景 10：周报连续性断链

输入条件：用户要求写周报，但读取不到上周周报，或本周日报不完整。

预期导师等级：不因数据缺失自动进入重度导师；先进入异常处理和证据链补全。

必须问的问题：缺少哪份上周周报或本周日报、哪些上周承诺需要用户补充确认、哪些本周执行事实缺少证据？

不应该做的事：不得假装已经读取完整周报和日报；不得让上周承诺无声消失；不得只根据用户一句话生成完整周报。

通过标准：AI 标注“缺少上周周报基线”或“本周日报证据链不完整”，用当前 OKR、本周任务和用户补充重建复盘基线，并在周报风险或待确认事项中体现。

失败表现：缺少上周周报仍直接写周报；没有提示连续性缺口；未追问上周计划完成状态。

## 场景 11：跨周重复问题升级

输入条件：上周周报或最近日报显示同一类问题连续出现，例如同一 KR 连续延期、连续只有动作没有结果、同一依赖反复阻塞。

预期导师等级：中度导师；如果重复问题导致核心 KR 明显落后或目标达成概率下降，升级为重度导师。

必须问的问题：这个问题已经重复几次、为什么上周补救没有解决、它影响哪个 KR、下周要升级/砍范围/加资源/换方法/调整计划中的哪一种？

不应该做的事：不得继续写“下周继续推进”；不得把重复问题当成普通本周风险；不得跳过系统性原因。

通过标准：AI 将同类问题升级为系统性执行风险，写入周报问题风险或经验复盘，并把明确纠偏动作放入下周计划或需协助 / 需决策事项。

失败表现：连续两周同类问题仍只写成“本周受阻”；没有解释上周补救为什么失效；下周计划没有针对性动作。

## 场景 12：周度 OKR 健康度判断

输入条件：用户要求写周报，本周有 OKR/KR、上周承诺、本周日报和任务数据。

预期导师等级：按健康度决定；健康通常轻度，偏慢通常中度，危险通常中度或重度。

必须问的问题：本周 KR 实际推进是否达到预期、最大 KR 缺口是否缩小、下周计划是否足以提高达成概率？

不应该做的事：不得只写“存在风险”；不得没有依据地给健康度；不得健康度为偏慢或危险却不安排纠偏动作。

通过标准：AI 输出健康、偏慢或危险之一，并说明依据；偏慢或危险时，下周计划中必须包含对应纠偏动作。

失败表现：没有健康度；健康度和事实矛盾；风险判断没有进入下周计划。

## 场景 13：OKR 达成概率判断

输入条件：用户要求写周报，当前 OKR 周期还有剩余时间，KR 有当前进度、目标或可判断里程碑。

预期导师等级：达成概率高通常轻度；中通常中度；低通常中度或重度。

必须问的问题：当前周期还剩多少工作日、最大 KR 缺口是什么、按当前速度能不能完成、下周哪 1-3 个动作最能提高达成概率？

不应该做的事：不得只写“存在风险”；不得没有依据地判断高 / 中 / 低；不得达成概率中或低却没有下周加速动作。

通过标准：AI 输出 OKR 达成概率高 / 中 / 低，说明依据，并把提高达成概率的动作放入下周计划或协助事项。

失败表现：没有达成概率；达成概率与 KR 速度矛盾；没有把风险转化成下周动作。

## 场景 14：KR 推进速度判断

输入条件：用户要求写周报，本周涉及多个 KR，其中至少一个 KR 有推进不足、停滞或无法量化的情况。

预期导师等级：单个 KR 偏慢通常中度；核心 KR 停滞或倒退通常重度。

必须问的问题：每个重点 KR 本周新增推进是什么、剩余缺口是什么、实际速度和所需速度差多少、下周如何加速？

不应该做的事：不得只写本周做了哪些动作；不得把准备动作当成 KR 推进；不得忽略停滞 KR。

通过标准：AI 逐项输出重点 KR 推进速度：超预期 / 正常 / 偏慢 / 停滞 / 倒退；对偏慢、停滞或倒退 KR 形成下周可验收纠偏动作。

失败表现：没有逐项判断 KR 速度；把无结果动作写成正常推进；下周计划没有补最慢 KR。
