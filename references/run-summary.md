# 运行摘要规范

## 作用

运行摘要用于解释本次日报/周报工作流“依据了什么、为什么这样判断、写入了什么、还有什么没写入”。它只增强透明度，不改变主流程，不增加新的导师追问项。

## 输出时机

必须在以下节点输出运行摘要：

- 进入日报草稿前：说明本次读取了哪些数据、总 OKR 风险预估结果、还缺什么信息、为什么可以起草。
- 进入周报草稿前：说明本次读取了哪些上周周报、本周日报、本周任务、OKR/KR、复盘记录和周报规则，周度 OKR 健康度、OKR 达成概率、KR 推进速度、关键周度偏差和跨周重复问题是什么。
- 提交前确认时：说明将生成哪些手动填写日报/周报字段、哪些今日任务将勾选完成、哪些明日/下周飞书任务将创建或更新、哪些复盘 Base 记录将写入。
- 写入完成后：说明手动填写稿生成状态、任务勾选完成、任务创建或更新、Base 的写入结果和校验结果。
- 停止写入时：说明停止原因，例如配置未完成、权限不足、信息不足或用户未确认。
- 部分写入失败时：说明成功项、失败项、失败原因和重试前需要用户确认的内容。

## 固定格式

默认使用以下结构，控制在 8 行以内：

```text
本次运行摘要：
- 数据来源：
- 导师等级：
- 关键判断：
- 写入状态：
- 未写入 / 待确认：
```

## 字段规则

- `数据来源`：列出实际使用的数据，例如当前 OKR、KR 进度、截止日期、昨日明日计划、上周周报、本周全部日报、今日飞书任务、用户补充信息、复盘 Base。
- `导师等级`：写轻度导师、中度导师、重度导师或未进入导师模式，并用一句话说明依据。
- `关键判断`：列出 1-3 条最重要判断，例如“完成撰写但未发布，因此算产物完成，不算流量结果”；若有 OKR 风险，必须写最大 KR 缺口、剩余工作日、最低日均推进要求和保 OKR 动作；周报场景必须写周度 OKR 健康度、OKR 达成概率、重点 KR 推进速度及其依据，若发现跨周重复问题必须写明重复问题和纠偏方向。
- `写入状态`：说明日报/周报正文手动填写稿、今日任务勾选完成、明日/下周飞书任务、复盘 Base 是已生成、已写入、待确认、未写入还是部分失败。
- `未写入 / 待确认`：说明因信息不足、权限不足、配置未完成、用户未确认、不任务化、不满足完成条件或 OKR 保证动作未确认而未写入的内容。

## 边界

- 不做质量评分。
- 不记录完整推理过程。
- 不输出 open_id、token、字段 ID 等敏感标识，除非用户正在做团队迁移校验且需要检查配置。
- 不把未经确认的推断写成事实；推断必须标注“我推断”或“看起来”。
- 不把运行摘要同步到飞书，除非用户明确要求。

## 示例

```text
本次运行摘要：
- 数据来源：昨日明日计划、今日飞书任务、当前 OKR、用户补充信息
- 导师等级：中度导师，原因是核心计划未完成且影响 KR
- 关键判断：3 篇笔记完成撰写但未发布，因此算产物完成，不算流量结果
- 写入状态：日报待确认；今日任务勾选完成预览 2 条；明日任务预览 3 条；复盘 Base 待确认 1 条
- 未写入 / 待确认：日报/周报正文等待用户手动提交；AI 工具成本控制需补任务验收标准
```
