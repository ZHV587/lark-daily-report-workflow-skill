# 语义触发规则

## 目标

本技能通过语义触发，不要求团队成员记固定口令。必须先识别用户意图，再选择工作层级；默认只读，显式升级，确认写入。任务查询不等于日报/周报复盘，任务诊断不等于汇报提交，汇报草稿不等于飞书写入。

用户只是询问任务清单、逾期任务、今日安排、任务优先级或飞书任务详情时，默认进入 `TASK_QUERY`，不得自动进入日报或周报复盘，不得追问未完成根因，不得生成汇报草稿，不得创建、更新、完成飞书任务，不得写入复盘 Base。

## 工作层级

- `TASK_QUERY`：任务查询模式。只读飞书任务，可辅助读取 OKR 做轻量标注；输出今日任务、逾期任务、已完成/未完成、建议优先级和可能关联的 KR。不追问、不复盘、不写入。
- `TASK_DIAGNOSIS`：执行诊断模式。分析未完成、逾期、风险、阻塞、偏离或假进展；可提醒 OKR 影响，但不默认写日报。升级到日报复盘前必须确认。
- `REPORT_REVIEW`：日报复盘模式。用户明确要写日报、填日报、开始日报复盘或按日报规范整理后，才读取昨日“明日计划”、今日任务、OKR 和日报规则，按规范追问根因、补救方案、明日计划和复盘记录。
- `WEEKLY_REPORT_REVIEW`：周报复盘模式。用户明确要写周报、本周复盘、生成周报、按周报规范整理或制定下周计划后，读取本周日报、本周任务、OKR/KR 和周报规则，按周报规范复盘本周 KR 推进、偏差、风险、方法沉淀和下周计划。
- `WRITE_PREVIEW` / `WRITE_VERIFY`：写入执行模式。用户明确要求提交、写入、创建明日任务、同步 Base 或完成任务时，先展示预览并获得明确确认；写入后必须回读校验。

每次响应开始时，必须用一句话声明当前模式，例如：

```text
我先按任务查询模式处理，只看任务清单，不进入日报复盘。
```

```text
我现在进入日报复盘模式，会按规范追问未完成原因和补救方案。
```

```text
我现在进入周报复盘模式，会围绕本周 KR 推进、偏差和下周计划来整理。
```

## 强触发

出现以下意图时，直接进入 `REPORT_REVIEW`，但仍不得直接写入飞书：

- 写日报、填日报、提交日报、飞书日报、今日日报、工作日报。
- 日报复盘、OKR 日报、OKR 执行复盘。
- 按日报规范整理、生成日报草稿、开始日报复盘。
- 昨天的明日计划、今日计划复盘、明日计划复盘。
- 把明天计划变成飞书任务、制定明日计划并任务化。
- 同步复盘反思、写入复盘 Base、复盘反思多维表格。

出现以下意图时，直接进入 `WEEKLY_REPORT_REVIEW`，但仍不得直接写入飞书：

- 写周报、填周报、提交周报、飞书周报、工作周报。
- 周报复盘、OKR 周报、本周复盘、本周 OKR 复盘。
- 按周报规范整理、生成周报草稿、开始周报复盘。
- 本周目标回顾、本周重点工作、本周核心成果、本周问题与风险。
- 方法沉淀、下周计划、制定下周计划并任务化。

强触发后，先读取必要上下文，不要再问“是否进入汇报流程”。如果缺少权限、身份或团队配置，按首次运行或异常流程处理。提交日报/周报、写入飞书、创建或更新飞书任务、同步复盘 Base、批量完成任务属于写入意图，必须进入 `WRITE_PREVIEW`，展示预览并获得明确确认后才能执行；其中“提交日报/填日报/提交周报/填周报”默认解释为生成手动填写稿和提交检查清单，不自动操控飞书提交正文。

## 中触发

出现以下意图时，进入 `TASK_DIAGNOSIS` 或先确认是否升级，不得直接生成日报：

- 这个任务没完成、这个任务为什么逾期。
- 哪些任务没完成，以及这些未完成会不会影响 OKR。
- 根据 OKR 梳理今天或明天要做什么。
- 复盘今天、分析风险、找执行偏差。
- 检查今天做的事情是否推进 OKR。
- 制定明天计划、安排明天任务。
- 梳理本周进展、分析本周风险、安排下周任务，但没有明确说写周报。

中触发时，先声明诊断模式，分析事实、影响和风险，再问一句：

```text
要不要把这个纳入今天的 OKR 日报复盘？如果你是要做整周复盘，我可以切到周报复盘。
```

只有用户确认后，才升级到 `REPORT_REVIEW`。

## 弱触发

出现以下模糊表达时，默认进入 `TASK_QUERY` 或普通整理，不直接生成日报：

- 我今天有哪些任务。
- 还有哪些事没做。
- 哪些任务逾期。
- 帮我看下飞书任务。
- 今天先做什么。
- 我今天做了这些。
- 帮我总结一下今天。
- 明天该做什么。
- 帮我整理一下工作。
- 看下我现在还有什么事。

任务查询类弱触发标准话术：

```text
我先按任务查询模式处理，只看任务清单，不进入日报复盘。
```

普通整理类弱触发如需升级，确认话术：

```text
你是想进入 OKR 日报复盘，把今日执行、未完成原因、明日计划和飞书任务一起梳理吗？
```

用户确认后进入日报工作流；用户否认时，只做普通总结或任务梳理，不执行日报提交、Base 写入或飞书任务写入。

## 误触发边界

以下情况不得自动进入日报工作流：

- 用户只是询问今天有哪些任务、还有哪些事、哪些逾期、今天先做什么、任务优先级。
- 用户只是询问某个飞书任务的详情。
- 用户只是要求创建单条飞书任务。
- 用户只是查询 OKR，不涉及今日执行或日报复盘。
- 用户只是写普通项目总结、会议纪要或非 OKR 周报/月报。
- 用户只是让 AI 润色一段文字，不涉及日报模板或 OKR 执行。

如果用户后续提到日报、周报、今日计划复盘、明日计划复盘、本周复盘、OKR 执行复盘或复盘反思，再切入对应层级。

## 升级、降级与退出

- `TASK_QUERY` 可以直接结束；只在用户继续讨论未完成、逾期原因、风险、OKR 影响或补救方案时，升级到 `TASK_DIAGNOSIS`。
- `TASK_DIAGNOSIS` 只有在用户确认“纳入日报”“开始日报复盘”“写日报”等意图后，升级到 `REPORT_REVIEW`；确认“纳入周报”“本周复盘”“写周报”等意图后，升级到 `WEEKLY_REPORT_REVIEW`。
- `REPORT_REVIEW` 只有在日报字段、明日计划、复盘 Base 记录和飞书任务预览都通过规范检查并获得用户明确确认后，升级到 `WRITE_PREVIEW` 或 `WRITE_VERIFY`。
- 用户说“暂停日报”“先不写日报”“只是看看任务”“先别提交”“不写入飞书”“不用复盘”等表达时，立即退出 `REPORT_REVIEW` 或降级到 `TASK_QUERY`/普通对话，不得继续沿用日报追问状态。
- 未进入 `REPORT_REVIEW` 前，不得强制用户解释每个未完成项的根本原因。

## 进入工作流后的第一步

进入 `REPORT_REVIEW` 后先说明将按日报闭环处理，并开始读取上下文：

```text
我会按 OKR 日报闭环来处理：先读取昨日明日计划、今日飞书任务和当前 OKR，再和你一起复盘今日执行、未完成原因、明日计划和需要写入飞书的任务。
```

如果是同事首次运行、身份不确定或权限不确定，先执行 `first-run-checklist.md`，不得直接写入飞书。

进入 `WEEKLY_REPORT_REVIEW` 后先说明将按周报闭环处理，并开始读取上下文：

```text
我会按 OKR 周报闭环来处理：先读取本周日报、本周飞书任务和当前 OKR，再和你一起复盘本周 KR 推进、偏差风险、方法沉淀和下周计划。
```
