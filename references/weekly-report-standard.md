# 周报填写规范

## 核心目的

周报用于判断本周是否偏离本人 OKR，并决定下周优先级、纠偏动作和方法沉淀。周报不是把本周日报合并成一篇流水账，而是围绕本周重点 KR 做结果复盘。

周报核心链路：

`本周 OKR / KR 目标 -> 本周执行事实 -> KR 推进验证 -> 偏差复盘 -> 方法沉淀 -> 下周计划`

## 规则配置

- 规则名称：`工作周报：本人 OKR 周复盘`
- 提交人：所有需要执行 OKR 的成员
- 接收人：直属上级
- 提交频率：每周五
- 提交时间：18:00 前
- OKR 插入位置：`本周目标回顾`
- OKR 插入要求：插入本人本周重点推进的 OKR / KR

## 字段规范

### 本周目标回顾

插入本人本周重点推进的 OKR / KR，并写清预期结果、实际结果、完成度和偏差原因。不得插入上级或他人 OKR；上级 OKR 只能通过对齐关系承接。

### 本周重点工作

按本人 KR 写推进情况，不堆砌日报流水账。每项工作必须说明服务哪个 KR、做了什么、产出是什么、是否推进了 KR。

### 本周核心成果

写关键数据、交付物、业务结论，以及这些成果如何支撑上级目标。必须区分“做了动作”和“形成结果”；只有动作没有数据、交付物或结论时，应标注为过程进展。

### 本周问题与风险

写哪些本人 KR 存在风险、原因是什么、当前如何处理、后续风险是什么。必须包含影响范围、剩余时间、需要调整的优先级、资源或决策需求。

### 本周经验复盘

写本周有效动作、无效动作、原因分析和下周改进动作。复盘必须能指导下周执行，不能只写感受。

### 方法沉淀

写本周新增或优化的 SOP、模板、流程、话术、标准或避坑清单。没有形成可复用方法时，明确写“暂无”，并说明下周是否需要沉淀。

### 下周计划

写下周优先推进的本人 KR、预期结果和截止时间。下周计划必须承接本周未完成、风险项和最大 KR 缺口；每项核心动作要有优先级、验收标准和任务化建议。

### 需协助 / 需决策事项

写需要谁支持、需要做什么、期望完成时间和不处理的影响。确实没有时填写“暂无”。

## 周报必须读取和核验的数据

- 本人当前 OKR / KR、进度、截止日期和剩余工作日。
- 本周已提交日报，重点读取每日目标、完成、问题风险、经验复盘和明日计划。
- 本周飞书任务：已完成、未完成、逾期、延期、下周到期。
- 本周已同步的复盘 Base 记录。
- 用户补充的实际结果、数据、交付物和关键判断。

## 周报复盘方式

周报开场先做本周 OKR 风险回顾：

- 本周重点 Objective / KR 是什么。
- 本周 KR 预期推进是什么。
- 实际推进到哪里。
- 最大偏差和最大风险是什么。
- 下周最需要纠偏的 1-3 个动作是什么。

周报追问围绕 KR，不按日期逐条审问。只有日报中出现重复延期、连续无 KR 推进、忙但不推进 KR、风险反复出现或方法无沉淀时，才进入中度或重度导师追问。

## 下周计划任务化

下周计划中的核心执行项应创建或更新飞书任务。每条任务至少包含：

- 任务标题。
- 对应目标 / KR。
- 截止日期。
- 优先级。
- 可验收标准。
- 来源周报日期。

由本周未完成、受阻或高风险事项产生的纠偏动作默认必须任务化。纯复盘、方法原则、观察项或暂无法定义下一动作的内容可以不任务化，但必须说明原因。

## 提交前自检清单

- 是否插入本人 OKR / KR，而不是上级或他人 OKR。
- 本周目标是否写清预期结果、实际结果、完成度和偏差原因。
- 本周重点工作是否按 KR 组织，而不是按日期罗列。
- 核心成果是否有数据、交付物或明确结论。
- 问题与风险是否写清影响、原因、处理方式和后续风险。
- 经验复盘是否能转化为下周改进动作。
- 方法沉淀是否有 SOP、模板、流程、话术、标准或明确写暂无。
- 下周计划是否承接最大 KR 缺口和本周未完成 / 风险项。
- 下周核心执行项是否已形成任务预览。
- 需协助事项是否写清对象、动作、时间和不处理的影响。
