# 周报填写规范

## 核心目的

周报用于判断本周是否偏离本人 OKR，并决定下周优先级、纠偏动作和方法沉淀。周报不是把本周日报合并成一篇流水账，而是围绕本周重点 KR 做结果复盘。

周报核心链路：

`上周周报下周计划 -> 本周全部日报 -> 本周执行事实 -> KR 推进验证 -> 偏差复盘 -> 方法沉淀 -> 下周计划`

## 规则配置

- 规则名称：`工作周报：本人 OKR 周复盘`
- 提交人：所有需要执行 OKR 的成员
- 接收人：直属上级
- 提交频率：每周五
- 提交时间：18:00 前
- OKR 插入位置：`本周目标回顾`
- OKR 插入要求：插入本人本周重点推进的 OKR / KR

## 字段规范

### 本周目标回顾

插入本人本周重点推进的 OKR / KR，并写清预期结果、实际结果、完成度和偏差原因。不得插入上级或他人 OKR；上级 OKR 只能通过对齐关系承接。

### 本周重点工作

按本人 KR 写推进情况，不堆砌日报流水账。每项工作必须说明服务哪个 KR、做了什么、产出是什么、是否推进了 KR。

### 本周核心成果

写关键数据、交付物、业务结论，以及这些成果如何支撑上级目标。必须区分“做了动作”和“形成结果”；只有动作没有数据、交付物或结论时，应标注为过程进展。

### 本周问题与风险

写哪些本人 KR 存在风险、原因是什么、当前如何处理、后续风险是什么。必须包含影响范围、剩余时间、需要调整的优先级、资源或决策需求。

### 本周经验复盘

写本周有效动作、无效动作、原因分析和下周改进动作。复盘必须能指导下周执行，不能只写感受。

### 方法沉淀

写本周新增或优化的 SOP、模板、流程、话术、标准或避坑清单。没有形成可复用方法时，明确写“暂无”，并说明下周是否需要沉淀。

### 下周计划

写下周优先推进的本人 KR、预期结果和截止时间。下周计划必须承接本周未完成、风险项和最大 KR 缺口；每项核心动作要有优先级、验收标准和任务化建议。

### 需协助 / 需决策事项

写需要谁支持、需要做什么、期望完成时间和不处理的影响。确实没有时填写“暂无”。

## 周报必须读取和核验的数据

- 本人当前 OKR / KR、进度、截止日期和剩余工作日。
- 上周已提交周报，重点读取“下周计划”、问题与风险、需协助 / 需决策事项、方法沉淀和未完成承诺。
- 本周全部已提交日报，重点读取每日目标、完成、问题风险、经验复盘和明日计划。
- 本周飞书任务：已完成、未完成、逾期、延期、下周到期。
- 本周已同步的复盘 Base 记录。
- 用户补充的实际结果、数据、交付物和关键判断。

## 周报连续性规则

周报必须回顾上周周报和本周全部日报。上周周报里的“下周计划”就是本周计划主干，不能被本周临时工作、任务列表或 AI 总结覆盖。

每条上周“下周计划”都必须核验：

- 是否完成。
- 完成到什么程度。
- 对应哪个 OKR / KR。
- 证据来自哪篇本周日报、飞书任务、数据或用户确认。
- 未完成、部分完成、受阻、取消或顺延的原因是什么。
- 是否需要进入下周计划、协助事项、风险升级或明确取消。

本周全部日报用于还原每天的执行事实、计划变化、风险变化和经验复盘。周报不能只摘取完成得好看的事项；如果日报里出现重复延期、连续无 KR 推进、忙但不推进 KR、风险反复出现或明日计划不断改口，必须在周报问题风险或经验复盘中体现，并讨论下周如何纠偏。

如果没有读取到上周周报，不得假装有连续性；必须标注“缺少上周周报基线”，并用当前 OKR、本周全部日报、本周任务和用户补充重建本周复盘基线。如果本周日报缺失，必须标注“本周日报证据链不完整”，并让用户补充关键执行事实。

## 周报复盘方式

周报开场先做本周 OKR 风险回顾：

- 上周周报承诺本周要完成什么。
- 本周重点 Objective / KR 是什么。
- 本周 KR 预期推进是什么。
- 实际推进到哪里。
- 周度 OKR 健康度是什么。
- 最大偏差和最大风险是什么。
- 下周最需要纠偏的 1-3 个动作是什么。

周报追问围绕 KR，不按日期逐条审问。只有日报中出现重复延期、连续无 KR 推进、忙但不推进 KR、风险反复出现或方法无沉淀时，才进入中度或重度导师追问。

## 周度 OKR 健康度

周报必须输出周度 OKR 健康度，不能只写“有风险”。健康度用于让用户快速判断本周是否还在正确轨道上。

健康度分为：

- 健康：本周关键 KR 按预期推进，核心承诺大部分完成，风险可控，下周计划能自然承接。
- 偏慢：关键 KR 有推进但低于预期，存在未完成或受阻项，下周需要加速或调整优先级。
- 危险：核心 KR 基本无推进、最大缺口没有承接、连续延期或本周动作无法支撑 OKR 达成，需要升级、砍范围、加资源或重排计划。

判断健康度时至少检查：

- 上周周报“下周计划”的完成率和关键承诺完成情况。
- 本周重点 KR 的预期推进与实际推进差距。
- 最大 KR 缺口是否变小，还是继续扩大。
- 本周是否出现忙但不推进 KR 的假进展。
- 下周计划是否足以提高 OKR 达成概率。

健康度必须写入运行摘要或周报草稿前的复盘引导。若判断为“偏慢”或“危险”，必须说明原因，并在下周计划中安排对应纠偏动作。

## 跨周重复问题识别

周报必须检查上周周报、本周全部日报和本周问题风险中是否出现同类问题。如果连续两周以上出现同类问题，不能继续按普通单周问题处理，必须升级为系统性执行风险。

常见跨周重复问题包括：

- 同一 KR 或同一核心计划连续延期。
- 同一外部依赖反复阻塞，例如样品、数据、权限、协作人未到位。
- 连续出现“做了动作但没有数据 / 结果 / 发布 / 闭环”。
- 连续出现非 OKR 工作挤占核心计划。
- 连续没有形成 SOP、模板、标准或方法沉淀。

跨周重复问题必须输出：

- 重复问题是什么。
- 已连续出现几周或几次。
- 影响哪个 OKR / KR。
- 为什么之前的补救没有解决。
- 本周要不要升级、砍范围、加资源、换方法或调整计划。
- 下周用什么可验收动作验证问题已被解决。

如果用户无法确认是否跨周重复，标注为“疑似跨周重复问题”，并把确认动作放入下周计划或待确认事项。

## 下周计划任务化

下周计划中的核心执行项应创建或更新飞书任务。每条任务至少包含：

- 任务标题。
- 对应目标 / KR。
- 截止日期。
- 优先级。
- 可验收标准。
- 来源周报日期。

由本周未完成、受阻或高风险事项产生的纠偏动作默认必须任务化。纯复盘、方法原则、观察项或暂无法定义下一动作的内容可以不任务化，但必须说明原因。

## 提交前自检清单

- 是否插入本人 OKR / KR，而不是上级或他人 OKR。
- 是否读取上周周报，并逐项核验上周“下周计划”的完成、受阻、取消或顺延状态。
- 是否读取本周全部日报，并把日报作为本周执行事实和计划变化证据。
- 是否输出周度 OKR 健康度，并说明健康、偏慢或危险的依据。
- 是否识别跨周重复问题；若连续两周出现同类问题，是否升级为系统性执行风险。
- 本周目标是否写清预期结果、实际结果、完成度和偏差原因。
- 本周重点工作是否按 KR 组织，而不是按日期罗列。
- 核心成果是否有数据、交付物或明确结论。
- 问题与风险是否写清影响、原因、处理方式和后续风险。
- 经验复盘是否能转化为下周改进动作。
- 方法沉淀是否有 SOP、模板、流程、话术、标准或明确写暂无。
- 下周计划是否承接最大 KR 缺口和本周未完成 / 风险项。
- 下周计划是否包含健康度偏慢 / 危险或跨周重复问题对应的纠偏动作。
- 下周核心执行项是否已形成任务预览。
- 需协助事项是否写清对象、动作、时间和不处理的影响。
