# 月报填写规范

## 核心目的

月报用于复盘本月 OKR 目标达成、能力成长和方法沉淀，并决定下月如何提高目标达成概率。月报不是把周报拉长，也不是把日报拼接成流水账；月报必须先逐篇复盘本月全部日报和全部周报，形成月度证据账本，再压缩成可填写到飞书的字段稿。

月报核心链路：

`上月月报下月计划 -> 本月全部周报 -> 本月全部日报 -> 月度执行事实 -> KR 月度结果验证 -> 偏差复盘 -> 能力成长复盘 -> 方法沉淀 -> 下月目标与计划`

## 规则配置

- 规则名称：`月度复盘：目标达成与能力沉淀`
- 提交人：所有需要执行 OKR 的成员
- 接收人：直属上级
- 提交频率：每月一次
- OKR 插入位置：`本月目标回顾`
- OKR 插入要求：插入本人完整月度 OKR，并写清预期结果、实际结果、完成度和偏差原因。

规则 ID、字段 ID、提交窗口和接收人以运行时读取和 `team-config.local.md` 为准；公共配置中不得硬编码个人 open_id、个人 OKR 或团队专属资源 ID。

## 必须读取的数据

- 本人当前 OKR / KR、进度、截止日期、指标口径和本月周期信息。
- 上月已提交月报，重点读取“下月目标与计划”和“资源 / 协作 / 决策需求”。
- 本月全部已提交周报，重点读取目标回顾、核心成果、问题风险、经验复盘、方法沉淀、下周计划、周度健康度、OKR 达成概率和 KR 推进速度。
- 本月全部已提交日报，重点读取今日目标、今日完成、关键成果、问题风险、经验复盘、明日计划、OKR 风险预估、周中预警和 OKR 进度更新。
- 本月飞书任务：已完成、未完成、逾期、延期、取消、下月到期和无日期但与 OKR 相关的任务。
- 本月飞书 OKR 进展记录，核对日报/周报中的推进是否已经同步。
- 本月复盘 Base 记录，用于识别重复偏差、能力短板和可沉淀方法。
- 用户补充的实际结果、业务数据、交付物、外部依赖和关键判断。

## 月度证据账本

月报起草前必须形成内部 `月度证据账本`。账本不必全文写进月报，但必须支撑月报中的每个关键判断。

每篇日报至少记录：

- 日期。
- 今日目标来源：昨日明日计划、本周周报计划、飞书任务、临时重点或 OKR 风险校准。
- 对应 Objective / KR。
- 完成状态：完成、部分完成、受阻、取消或顺延。
- KR 推进事实、产物、数据或证据。
- 未完成根因、KR 影响和用户确认过的补救方案。
- 明日计划是否承接未完成项和最大 KR 缺口。
- 是否生成或漏掉 OKR 进度更新。
- 经验复盘可沉淀内容。

每篇周报至少记录：

- 周期。
- 上周“下周计划”的完成状态。
- 本周重点 KR、预期结果、实际结果和完成度。
- 周度 OKR 健康度、OKR 达成概率和 KR 推进速度。
- 周中预警是否纠偏。
- 跨周重复问题和个人重复偏差画像。
- 方法沉淀和可复用资产。
- 下周计划是否能提高 OKR 达成概率。

不得抽样复盘，不得只看印象深的日报或周报，不得只挑完成得好看的内容。如果缺少任一应提交日报、周报或上月月报，必须标注证据缺口，并说明对月度判断的影响。

## 字段规范

### 本月目标回顾

插入本人完整月度 OKR，并写清预期结果、实际结果、完成度和偏差原因。目标回顾必须从上月月报“下月目标与计划”开始核验，再结合本月周报、日报、任务和 OKR 进展判断。

必须包含：

- 本月 Objective / KR。
- 月初预期结果。
- 月末实际结果。
- 完成度：完成、部分完成、受阻、取消或调整。
- 偏差原因和数据来源可信度。
- OKR/KR 变更记录；无变更时写“本月暂无已确认 OKR/KR 变更”。

### 本月重点工作

按本人 KR 组织重点工作，不按日期罗列。每项重点工作必须说明服务哪个 KR、做了什么、产出是什么、是否推进 KR，以及证据来自哪些日报、周报、任务或数据。

### 本月核心成果

写本月最重要的结果、关键数据、代表性交付物和业务价值。必须区分“做了动作”和“形成结果”；只有准备、沟通、撰写或搭建但没有业务结果时，写成阶段进展，不得包装成核心成果。

### 本月问题与风险

写主要偏差、深层原因、已采取措施、后续风险和需要的支持。必须覆盖：

- 本月最大 KR 缺口。
- 偏慢、停滞或倒退的 KR。
- 跨周重复问题。
- 周中预警未纠偏事项。
- 外部依赖、资源、协作或决策阻塞。
- 如果下月不处理，对 OKR 达成的影响。

### 本月经验复盘

写本月做得好的地方、做得不够好的地方、原因分析和下月改进动作。经验复盘必须来自日报经验复盘、周报经验复盘和复盘 Base，不得只写感受。

### 能力成长复盘

写本月提升的能力、体现在哪些事情上、暴露出的短板和下月重点提升方向。能力成长必须落到具体事情和证据上，例如内容测试、选品判断、SOP 建设、团队协作、数据分析、AI 协作等；不得只写“能力提升明显”。

### 方法 / 经验沉淀

写本月形成的 SOP、流程、模板、话术、标准或经验。每项沉淀要说明使用场景、适用边界、下月如何验证。如果没有形成可复用方法，明确写“暂无稳定方法沉淀”，并把补沉淀动作放入下月计划。

### 下月目标与计划

写下月目标建议、预期结果、衡量标准和截止时间。下月计划必须承接本月未完成、跨周重复风险、能力短板、方法沉淀缺口和最大 KR 缺口。

每项 P0/P1 计划至少包含：

- 对应 Objective / KR。
- 具体动作。
- 预期结果或 KR 推进。
- 衡量标准。
- 截止时间。
- 依赖条件。
- 对 OKR 达成概率的影响：提升、维持、下降或无法判断。
- 是否需要创建或更新飞书任务。

### 资源 / 协作 / 决策需求

写需要谁支持、需要什么资源、希望完成时间和不处理的影响。确实没有时填写“暂无”。不能把真实阻塞藏起来；月报要把下月需要提前解决的依赖说清楚。

## 月度 OKR 达成概率

月报必须输出本周期或下月 OKR 达成概率：高、中或低。判断依据包括：

- 本月 KR 实际结果和剩余缺口。
- 本月实际推进速度与所需速度差距。
- 下月计划是否覆盖最大 KR 缺口。
- 跨周重复问题是否已有可验证纠偏动作。
- 资源、协作、决策和外部依赖是否可控。

达成概率为中或低时，不能只写“下月继续推进”；必须在下月计划或资源需求中安排加速、降范围、加资源、换方法、升级协助或目标调整动作。

## KR 月度推进速度

月报必须逐项判断重点 KR 的月度推进速度：

- 超预期：本月推进超过计划，或提前完成关键里程碑。
- 正常：本月推进基本符合计划，剩余缺口可控。
- 偏慢：本月有推进但低于计划，下月需要明显加速。
- 停滞：本月没有有效推进，只有准备动作、沟通动作或无结果动作。
- 倒退：进度、质量、资源或依赖状态变差，导致 KR 完成概率下降。

偏慢、停滞或倒退的 KR 必须进入“本月问题与风险”和“下月目标与计划”。

## OKR 进度核对与补写

月报必须核对本月所有日报、周报、飞书任务和用户确认事实中的 KR 推进，是否已经同步到飞书 OKR。

每个重点 KR 至少检查：

- 本月推进事实来自哪些日报、周报、任务或用户确认。
- 飞书 OKR 当前指标值、百分比、里程碑或最新进展记录。
- 是否存在漏同步。
- 是否存在重复写入或口径冲突。
- 建议补写方式：指标值、百分比、进展记录，或因口径/权限/重复风险暂不写入。

如发现 KR 实际推进但未同步 OKR，必须生成 `OKR 进度补写预览`。口径清楚、数据可信且没有重复风险时，补写是必做项；最终确认只确认补写内容是否准确，确认后通过 `lark-cli okr` 写入并回读校验。

## 导师式月度追问

月报追问要聚焦月度偏差，不按日期审问用户。出现以下情况时必须追问根因：

- 上月月报承诺本月要完成，但本月没有完成或没有证据。
- 同一问题跨周重复出现。
- 重点 KR 偏慢、停滞或倒退。
- 本月忙了很多，但核心 KR 没有结果。
- 周报多次提醒的风险没有被纠偏。
- 能力短板反复影响目标达成。
- 方法沉淀缺失，导致下月仍可能重复踩坑。

追问顺序：

1. 先说明事实和影响。
2. 问直接原因和根本原因。
3. 问原因是否可控。
4. 先让用户提出下月补救方案。
5. AI 再结合 OKR/KR、任务、依赖、产能和风险补充优化。
6. 用户确认后，写入月报、下月计划、飞书任务预览或资源需求。

## 提交前自检清单

- 是否读取并核验上月月报“下月目标与计划”。
- 是否读取本月全部周报，并逐篇纳入月度证据账本。
- 是否读取本月全部日报，并逐篇纳入月度证据账本。
- 是否标注缺失日报、缺失周报或缺失上月月报的证据缺口。
- 是否插入本人完整月度 OKR / KR，而不是上级或他人 OKR。
- 是否写清预期结果、实际结果、完成度和偏差原因。
- 是否输出月度 OKR 达成概率，并说明高、中、低的依据。
- 是否逐项判断 KR 月度推进速度。
- 是否核对本月 KR 推进是否已同步飞书 OKR；漏同步时是否生成 OKR 进度补写预览。
- 是否识别跨周重复问题和个人重复偏差画像。
- 是否复盘本月周中预警是否已纠偏。
- 是否写出能力成长和能力短板，并形成下月提升动作。
- 是否形成 SOP、模板、流程、话术、标准或明确写暂无及下月补动作。
- 下月计划是否承接最大 KR 缺口、本月未完成、跨周重复问题和能力短板。
- 下月计划是否写清预期结果、衡量标准、截止时间和任务化建议。
- 下月核心执行项是否形成飞书任务创建或更新预览。
- 资源 / 协作 / 决策需求是否写清对象、动作、时间和不处理的影响。
