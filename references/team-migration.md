# 团队迁移检查清单

## 硬规则

复制给新团队或新业务线前，必须先完成团队迁移检查。除非用户确认当前团队配置已完成校验，否则只能做草稿、手动填写稿和预览，不得写入飞书任务或 Base，不得声称已提交日报，不得写入复盘 Base，不得创建或更新飞书任务。

配置未完成、权限未确认或资源结构不一致时，停止写入流程，输出配置校验清单和缺口说明。

复制给同事时，默认同事也在自己的 Codex 中使用本技能完成日报。技能只提供流程、判断标准和飞书操作约束；不得携带原用户的身份、任务、OKR、日报实例或个人 open_id。同事运行前必须在本机或当前 Codex 环境完成 `lark-cli` 登录、身份确认和权限校验，并在运行时读取同事自己的 OKR、飞书任务、日报历史和复盘 Base 权限。

同事首次运行时，必须先执行 `first-run-checklist.md`。检查完成前只能输出草稿、任务预览、复盘 Base 预览和运行摘要，不得进行任何真实写入。

## 必改配置

复制后优先复制 `references/team-config.local.example.md` 为 `references/team-config.local.md`，并在本地覆盖文件中填写真实团队资源，不得沿用原团队资源：

- 日报规范文档 URL。
- 日报规则名称。
- 日报规则 ID。
- 时区。
- 工作日规则，不能默认所有团队都是周一到周六工作、周日休息。
- 日报字段列表，尤其确认是否存在 `小红书运营必做事项`。
- 复盘 Base 知识库节点。
- 多维表格 token。
- 数据表 ID。
- 视图 ID。
- 字段 ID 和字段类型。

`错误类型` 只能使用目标团队多维表格中已有选项。没有合适选项时留空，不得自动创建选项。

## 运行时资源校验

写入前必须重新读取并核对：

- 当前飞书用户身份。
- 日报规则存在，且名称和 ID 与配置一致。
- 日报字段存在，且字段名称与配置一致。
- Base、数据表、视图存在。
- Base 字段名称、字段 ID、字段类型与配置一致。
- `错误类型` 多选字段的可用选项。
- OKR 周期、目标、KR、进度和期限可读取。
- 今日飞书任务、逾期任务和已完成任务可读取。

校验结果必须在写入前向用户展示。用户未确认前，不得写入飞书。

## 权限校验

运行前必须执行权限校验，确认当前身份至少具备：

- 读取 OKR 周期、目标、KR 和进度的权限。
- 读取飞书任务的权限。
- 创建或更新飞书任务的权限。
- 读取日报规则、字段和历史日报的权限。
- 提交或更新日报的权限；若系统不支持提交接口，必须说明将使用桌面端兜底。
- 读取复盘 Base 字段、记录和选项的权限。
- 写入复盘 Base 记录的权限。

权限不足时，说明缺少的权限、影响范围和可继续的安全动作。安全动作只能包括读取已可访问数据、生成草稿、生成预览或输出配置缺口。

## 迁移后首轮运行

新团队第一次运行时，必须按以下顺序执行：

1. 读取 `team-config.md`。
2. 校验日报规则和日报字段。
3. 校验 OKR 可读性。
4. 校验飞书任务读取与任务写入权限。
5. 校验复盘 Base 结构与写入权限。
6. 生成一份不写入的日报草稿和任务预览。
7. 用户确认配置和权限都正确后，才允许真实写入。

## 配置未完成时

发现配置未完成、资源不存在、权限不足或结构漂移时：

- 不得写入飞书。
- 不得创建或更新飞书任务。
- 不得声称已提交日报；只能生成手动填写稿。
- 不得写入复盘 Base。
- 输出缺失配置、失败资源、影响范围和下一步修复建议。
- 可以继续生成日报草稿、明日计划草稿、复盘草稿和任务预览。
