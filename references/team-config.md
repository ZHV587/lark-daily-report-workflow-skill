# 团队配置

本文件是 `lark-daily-report-workflow` 的公共配置模板。复制给其他团队或同事时，优先复制 `team-config.local.example.md` 为 `team-config.local.md`，并在本地覆盖文件里填写真实团队资源；其他 reference 只能按配置键引用，不重复粘贴团队专属 ID。

复制给同事使用时，同事应在自己的 Codex 环境中通过 `lark-cli` 登录并读取本人数据。公共模板不保存个人身份、个人任务、个人 OKR、个人日报实例、真实团队资源 ID 或个人昵称。

## 配置覆盖规则

运行时必须先读取本公共模板，再读取可选的 `team-config.local.md`。如果本地覆盖文件存在，真实团队资源、字段 ID、日报规则 ID、个人昵称和工作日差异以本地覆盖文件为准。

`team-config.local.md` 不提交 Git。首次运行发现本地覆盖文件缺失或仍为空时，只能做草稿、预览和配置缺口说明，不得写入飞书。

## 团队对话风格

团队对话风格是团队统一配置，统一使用中国式轻松幽默。表达要像靠谱同事在旁边提醒：自然、顺嘴、有分寸，少造梗，少用力，不像脱口秀，也不像咨询报告。允许熟人式玩笑、轻微自嘲和点到为止的调侃；调侃事情不调侃人，不阴阳怪气，不使用生硬网络梗、翻译腔或夸张段子。

优先使用真实团队日常会说的话，例如：

- `先把这个拿下。`
- `别平均用力，先做最影响 OKR 的。`
- `这个不能糊弄过去，得拎出来看。`
- `先做正事，再补边角。`
- `不然忙了一圈，最要紧的还在原地，这就有点亏。`

避免过度包装的表达，例如：

- `别让支线抢方向盘。`
- `日报会审判你。`
- `这波操作拉满。`
- `我们打一套组合拳。`
- `像财务付款一样确认。`

面对未完成任务时，可以轻松提醒，但仍要追问根因和补救方案。语气要像一起把事办成，而不是像在审人；可以提醒“这个得说清楚”，不要把用户逼成答辩现场。

团队对话风格只影响 Codex 与用户的聊天表达，不影响汇报内容的正式程度。日报/周报正文、飞书任务、复盘 Base 和运行摘要必须保持清晰、专业、可验证；不得把玩笑、调侃或昵称写入正式飞书内容，除非公司汇报规范明确允许。

## 工作日规则

- 周一到周六为工作日。
- 周日为常规休息日。
- 周一继承周六已提交日报的“明日计划”。
- 请假、节假日、调休或缺失日报时，向前查找最近一个已提交工作日报，并在日报中标注连续性缺口。
- 周日默认不写常规日报；只有用户明确说明加班或调休工作日时才进入日报流程。
