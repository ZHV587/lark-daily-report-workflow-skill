# 日报填写规范

## 核心目的

日报用于纠正执行方向，保证每日执行持续推进 OKR，而不是罗列工作流水或自我证明。

日报工作流应体现 OKR 执行导师与目标北极星：北极星负责校准每项动作是否服务目标，导师负责在偏离、延期、假进展或目标风险出现时分级追问原因、挑战假设，并推动用户形成纠偏方案。

连续闭环：

`本周周报计划 -> 昨日明日计划 -> 今日计划 -> 今日执行 -> KR 推进验证 -> 偏差与经验复盘 -> 新明日计划`

规范来源：

见 `references/team-config.md` 的 `日报规范` 配置。

运行时优先读取知识库最新版；本文作为稳定基线。

## 字段规范

### 总 OKR 风险预估

日报草稿前必须先生成总 OKR 风险预估，用于决定今日复盘和明日计划的重点。该内容可以作为独立预览区，也可以并入“问题与风险”和“明日计划”，但写入前必须展示。

必须包含：

- 当前 Objective。
- 截止日期和剩余工作日。
- 全部 KR 的当前进度、目标值和剩余缺口；无法量化时说明用什么里程碑判断。
- 最大 KR 缺口。
- 最低日均推进要求；无法计算时说明缺少什么数据。
- 当前达成概率：高 / 中 / 低。
- 数据来源与可信度：飞书 OKR、飞书任务、日报/周报、Base、用户口述或 AI 推断；可信度为高 / 中 / 低。
- 今天复盘必须纠偏的方向。
- 明天最能提高 OKR 达成概率的 1-3 个动作。

如果最大 KR 缺口没有进入明日 P0 计划，日报不得提交，除非用户明确确认该 KR 已取消、目标已调整或另有负责人承接。

### OKR 变更记录

日报必须检查当前 OKR/KR 与最近可读取历史记录是否一致。以下任一变化都必须记录，不能静默覆盖：

- Objective、KR 名称或指标口径变化。
- KR 目标值、当前值、截止日期、权重、负责人或对齐关系变化。
- 周报计划或日报计划中对同一 KR 的判断口径发生变化。

变更记录至少包含：

- 变更项。
- 变更前 / 变更后。
- 变更来源：飞书 OKR、日报、周报、任务、用户口述或 AI 推断。
- 变更日期或发现日期。
- 变更原因；无法确认时写“原因待确认”。
- 对今日计划、本周计划、OKR 达成概率和明日 P0 的影响。

无法确认是否真实变更时，标注“疑似 OKR 变更，待确认”，并把确认动作写入待确认事项或明日验证动作。

### 数据可信度

所有关键判断必须标注数据来源和可信度。关键判断包括 KR 进度、剩余缺口、达成概率、周计划承接状态、任务完成状态、风险等级、保 OKR 动作和明日 P0 排序。

可信度分为：

- 高：来自飞书 OKR、飞书任务、已提交日报/周报、Base 记录或可验证数据，且信息一致。
- 中：来自用户口述或单一系统数据，能支撑判断但缺少交叉验证。
- 低：来自 AI 推断、信息缺失、口径冲突或无法读取完整数据。

低可信度信息不能写成确定事实，必须写为“待确认”“我推断”或“看起来”。如果低可信度判断会影响 OKR 达成概率、明日 P0 或任务勾选完成，必须先向用户确认。

### 周中预警

周中预警用于在周报结束前提前纠偏，避免到周报时才发现已经偏离。周一到周六的日报都可以触发；越接近周中后段，要求越严格。

出现以下任一情况时必须输出周中预警：

- 本周周报计划核心项没有进入昨日计划、今日任务或今日执行。
- 重点 KR 推进速度偏慢、停滞或只做准备动作没有结果。
- OKR 达成概率较上一份日报/周报下降，或最大 KR 缺口没有缩小。
- 同一计划连续顺延、重复延期或外部依赖反复阻塞。
- 今日临时事项挤占本周核心 KR，且没有补救安排。

周中预警至少包含：

- 触发原因。
- 影响的 Objective / KR。
- 如果不纠偏，到本周结束会造成什么后果。
- 今天或明天必须执行的纠偏动作。
- 是否需要协助、升级、缩小范围、换方法或调整优先级。

周中预警不能只停留在提醒，必须承接到明日计划、本周后续任务、协助事项或风险升级。

### OKR 周期累计风险

日报不能只判断今天和本周，还要轻量判断本 OKR 周期累计风险。该判断用于回答：按本周期剩余时间，明日计划是否真的能把目标往可达方向拉。

必须包含：

- 本周期剩余工作日。
- 最大 KR 累计缺口。
- 当前速度与最低日均推进要求的差距。
- 明日计划完成后，预计能缩小哪个 KR 缺口。
- 明日计划对 OKR 达成概率的影响：提升 / 维持 / 下降 / 无法判断。
- 如果明日计划不足以保 OKR，需要加速、降范围、加资源、换方法、调整优先级或升级决策中的哪一种。

如果明日计划完成后仍无法改善最大 KR 缺口，不得写成“保障 OKR”。必须写明“明日计划不足以保 OKR”，并形成补救动作或待决策事项。

### 个人重复偏差画像

当最近日报、周报或任务中连续出现同类执行偏差时，必须形成轻量的个人重复偏差画像。画像只描述可观察的执行模式，不评价人。

常见画像包括：

- 等外部依赖：关键动作反复卡在样品、数据、权限、协作人或审批。
- 写了没发布：产物完成但没有进入发布、验证或数据闭环。
- 准备多于结果：调研、整理、沟通较多，但 KR 结果没有形成。
- 临时事项挤占：非 OKR 工作反复挤占核心 KR。
- 计划过载：明日计划长期超过实际产能，导致反复顺延。

触发画像后必须写清：

- 重复模式是什么。
- 已出现几次或几天。
- 影响哪个 KR。
- 明天用什么预防动作避免再次发生。

画像必须服务纠偏，不得写成标签化评价。

### 今日目标

- 继承昨日日报的“明日计划”作为今日计划。
- 周一按团队规则继承周六日报；休息日或多日间隔按最近已提交工作日报处理。
- 读取最近一份有效周报的“下周计划”，作为本周周报计划，并核对今日计划是否承接本周主线。
- 主干必须逐项来自上一工作日日报的“明日计划”，不得用 OKR 风险、今日临时重点或 AI 总结另起新主题。
- 今日目标生成方式是：`昨日明日计划主干 + 本周周报计划校准 + OKR 风险校准 + 今日临时重点补充`。
- 每项继承计划必须标注对应目标/KR、动作类型、今天预期推动的指标、阶段结果或产物、验收标准。
- 每项本周周报计划必须标注今日状态：今日已承接、今日未承接但本周仍有效、已完成、受阻、取消或调整。
- 必须结合总 OKR 风险预估重新校准优先级：最大 KR 缺口相关计划优先写清为什么今天必须优先执行，不能平均用力。
- 今日临时重点可以加入，但必须标注来源、动作类型（核心动作、支撑动作或偏离动作）和对核心 KR 的占用影响；临时重点不得盖过昨日计划主干。
- 若上一工作日日报的“明日计划”缺失或为空，才允许用当前 OKR、今日飞书任务和用户确认事实重建今日目标，并在问题与风险或经验复盘中标注连续性缺口。
- 若最近一份有效周报缺失或周报“下周计划”为空，不得假装存在周计划基线；必须标注“周报计划基线缺失”，并用当前 OKR、昨日计划、今日任务和用户确认事实重建本周计划校准点。

### 今日完成

- 按今日计划逐项核对。
- 核对今日完成是否推进了本周周报计划；若今日完成与周报计划无关，说明是否属于必要临时事项、支撑动作或偏离动作。
- 写清动作、数量、完成状态和对应 KR。
- 对每个核心动作建立“动作到 OKR 因果链”：说明服务哪个 KR、对 KR 的推进是什么、如果不做对 OKR 有什么影响，并标注为核心动作、支撑动作或偏离动作。
- 临时新增事项注明来源及其对核心计划的影响。

### 关键成果

- 记录可验证的数据、交付物、链接、决策、反馈或结论。
- 区分“完成撰写”和“完成发布”、“开始使用”和“完成验证”。
- 不把动作本身冒充成果。

### 问题与风险

每项包含：

- 受影响的目标/KR。
- 影响程度和期限影响。
- 直接原因与根本原因。
- 已采取及下一步应对。
- 责任人、依赖和所需协助。
- OKR 完成风险下的保 OKR 动作、取舍动作和升级需求。

偏离动作或非 OKR 工作必须写清是否挤占核心 KR。需要做偏离行为纠正：说明为什么会做、是否必要、占用影响，以及后续砍掉、委派、延期或降优先级的处理方式。

出现以下情况时，问题与风险必须体现导师式干预结果，但干预强度要分级。一次性小偏差或单项轻微未完成使用轻度导师，写清偏差、一个关键原因和明日承接；影响 KR、任务逾期、非 OKR 工作挤占核心计划或明日计划过载使用中度导师，写清根因、KR 影响和用户确认的补救方案；重复延期、反复顺延、连续无 KR 推进、忙但不推进 KR 或目标达成概率明显下降等 OKR 风险使用重度导师，写清被挑战的假设、执行方式问题和取舍动作。

若用户无法提供更多信息，必须标注“信息不足”，并把后续确认动作写入待确认事项、风险或明日计划中的验证动作。

当 OKR 存在完成风险时，问题与风险不能只写“存在风险”或“继续推进”。必须写清最大 KR 缺口、截止日前剩余工作日、当前速度是否可达、需要立即执行的保 OKR 动作，以及哪些事项要暂缓、降级、委派或取消。

本周周报计划未被今日计划或今日任务承接时，必须写清是否构成周计划断链、影响哪个 KR、为何今天未承接，以及明日或本周后续如何补救。若用户决定取消或调整周报计划，必须说明原因和对 OKR 达成概率的影响。

若触发周中预警，问题与风险必须写清预警原因、影响 KR、数据来源与可信度、未纠偏后果和已经确认的纠偏动作。

### 经验复盘

每个独立经验写清：

- 发生了什么。
- 哪个做法有效或无效。
- 根本原因。
- 可复用的经验。
- 下一次的纠正动作。

该字段是“复盘反思”多维表格的唯一内容来源。

### 明日计划

每项包含：

- 优先级。
- 目标/KR。
- 具体动作。
- 预期 KR 推进、结果或产物。
- 可验收标准。
- 动作类型：核心动作、支撑动作或偏离动作。
- 不执行时对 OKR 的影响。

所有仍然有效的未完成、部分完成和受阻事项必须承接进明日计划，或者明确说明取消原因。结合 KR 缺口、期限、依赖和实际产能排序。

本周周报计划中仍有效但今日未承接的事项，必须优先判断是否进入明日计划、本周后续任务、协助事项或明确取消。若不进入明日计划，必须说明原因和不影响本周 OKR 推进的依据。

明日计划必须说明当前目标达成概率、最大 KR 缺口，以及明天最该做哪个动作来提高达成概率。无法现实支撑 OKR 达成时，写明需要资源、缩小范围、调整预期或升级处理。

明日计划必须做取舍：优先安排最能提高 OKR 达成概率的动作，明确哪些进入明天，哪些延期、委派、降级或不进入明天。不得用“全部继续推进”制造虚假承诺。

当 OKR 存在完成风险时，明日计划必须包含“保 OKR 方案”：最大 KR 缺口、截止日前剩余工作日、明天最关键的 1-3 个保 OKR 动作、每个动作的验收标准、被暂缓或降级的事项，以及需要资源、协助或升级决策的事项。

明日 P0 必须优先服务总 OKR 最大缺口。若 P0 计划未覆盖最大缺口，必须在日报中解释原因，并给出替代保障动作。

明日计划必须通过可执行性检查：

- 产能是否够：计划数量是否符合明天可用时间。
- 依赖是否清楚：样品、数据、权限、协作人是否到位。
- 验收是否明确：能否判断完成或未完成。
- KR 贡献是否明确：完成后预计推进哪个 KR。
- 是否覆盖最低推进要求：无法覆盖时，必须说明补救方式。
- 是否提高 OKR 达成概率：提升 / 维持 / 下降 / 无法判断。

计划过虚、过载、缺验收、依赖未到位或不能改善最大 KR 缺口时，必须先重排优先级，不能直接把所有事项塞进明日计划。

明日计划里的核心执行项必须创建或更新飞书任务。任务化字段至少包含：

- 任务标题。
- 对应目标/KR。
- 截止日期，通常是下一工作日。
- 优先级。
- 可验收标准。
- 来源日报日期。

纯复盘、风险观察、原则判断或暂无法定义下一动作的条目可以不创建任务，但必须写清不任务化原因。由未完成计划产生的补救动作默认必须任务化。

### 今日任务完成勾选

用户手动提交日报前必须根据今日飞书任务和用户确认事实，生成“今日任务完成勾选预览”。

可以勾选完成的任务必须有明确完成事实和可验证结果。部分完成、受阻、顺延、等待数据、等待真实闭环、明日继续承接或用户未确认的任务不得勾选完成。

预览必须分为：

- `将勾选完成`：任务标题、完成依据、对应今日完成事项。
- `不勾选完成`：任务标题、不勾选原因、后续去向。

用户明确确认后才允许调用 `lark-cli task +complete`。勾选后必须回读校验任务状态。

### 需协助 / 待确认事项

写清协助人、需要的动作、期望时间和不解决的影响。确实没有时填写“暂无”。

### 小红书运营必做事项

只选择事实已完成且符合团队规则的选项，不能用计划代替完成。

## 必须追问

对模糊表述追问数量、产物、状态、证据、结论和 KR 影响。

计划未完成时，必须问到：

1. 直接原因。
2. 根本原因。
3. 是否可控。
4. 对 KR 的影响。
5. 用户自己提出的补救方案。
6. AI 基于 OKR、任务、产能和风险补充优化后的补救方案。
7. 用户确认过的补救方案。
8. 是否顺延。
9. 所需资源或协助。

“时间不够”“事情太多”“还在推进”“等待中”不能直接作为最终原因。

补救方案不能由 AI 单方面决定。必须先让用户说明自己认为合理的补救方案，再由 AI 补充优化，最后让用户确认。

重复延期或反复顺延时，不能只写“继续推进”或“明天继续做”。这类情况默认属于重度导师场景，必须追问执行方式、优先级判断、资源配置或计划设计是否有问题，并让用户先提出避免再次发生的方案。

追问必须有停止条件。已获得事实、根因、KR 影响、补救方案和用户确认时停止追问；用户无法提供更多信息时标注信息不足；外部依赖无法短期解决时转入协助事项、升级动作或风险记录；继续追问不能改变明日计划或补救动作时停止重复追问。

## 提交前规范检查

不符合以下任一条件时不得提交：

- 所有模板字段完整。
- 已完成总 OKR 风险预估，包含最大 KR 缺口、剩余工作日、最低日均推进要求和当前达成概率。
- 已完成 OKR 周期累计风险判断，说明明日计划对达成概率的影响。
- 总 OKR 风险预估、KR 进度、任务完成状态和达成概率均已标注数据来源与可信度。
- OKR/KR 如有变化，已写清变更项、变更前后、来源、日期、原因和影响；疑似变化已进入待确认。
- 今日目标以昨日“明日计划”为主干，并已结合 OKR 风险校准优先级。
- 已读取并核对本周周报计划；每项周报计划都有今日状态和去向。
- 周报计划断链、冲突或偏离已说明原因、KR 影响和补救方案。
- 周中预警触发时，已形成明日计划、本周后续任务、协助事项或风险升级。
- 重复偏差出现时，已形成个人重复偏差画像和明日预防动作。
- 今日临时重点已标注来源、动作类型和是否挤占核心 KR。
- 昨日计划逐项有状态。
- 未完成项有根因、影响、用户确认过的补救方案和明确去向。
- 今日成果能够验证。
