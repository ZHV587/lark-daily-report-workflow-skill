# 飞书运行与写入规范

## 工具优先级

操控飞书的能力统一依托 `lark-cli` 与用户手动填写汇报分工完成。`lark-cli` 是读取、任务、Base 和回读校验的主路径；日报/周报正文只生成可复制到飞书汇报表单的手动填写稿，不自动操控飞书界面填写或提交。不得把汇报正文提交误判为 `lark-cli report`、开放 API 直接提交或 Computer Use 自动提交。

按以下顺序使用：

1. `lark-cli` 快捷命令：读取 OKR、任务、Base，创建/更新/完成任务，写入复盘 Base。
2. 已注册的 `lark-cli` 接口：优先用于结构化飞书资源操作。
3. 通过 `lark-cli api` 调用飞书原生开放接口：用于查询日报/周报规则和历史汇报等未封装读取能力。
4. 用户手动填写飞书日报/周报：AI 提供字段稿、勾选提示和提交前检查清单，用户自行复制、勾选并提交。

认证、身份切换或权限错误按 `lark-shared` 处理。OKR、任务和多维表格操作分别遵循对应飞书技能。

## 已核验命令族

当前已确认：

```powershell
lark-cli okr --help
lark-cli task --help
lark-cli base --help
```

可用快捷命令包括：

- OKR：`+cycle-list`、`+cycle-detail`、`+progress-list`、`+progress-get`、`+progress-create`、`+indicator-update`。
- 任务：`+get-my-tasks`、`+search`、`+create`、`+complete`、`+update`。
- Base：`+field-list`、`+field-get`、`+record-list`、`+record-search`、`+record-batch-create`、`+record-get`、`+record-upsert`。

查询参数前先运行：

```powershell
lark-cli schema <service.resource.method>
```

或查看具体快捷命令帮助：

```powershell
lark-cli okr +cycle-list --help
lark-cli task +get-my-tasks --help
lark-cli base +record-search --help
```

`lark-cli report --help` 当前返回“未知命令 report”的错误，因此不得在 Skill 中假设存在 `lark-cli report`。飞书开放平台“汇报”模块当前用于本工作流的稳定能力是查询规则和查询任务/历史；日报/周报正文默认只交付手动填写稿，由用户在飞书中自行提交。团队配置来自 `references/team-config.md`，不是本文件。

## 日报/周报正文手动填写路径

日报/周报正文必须交付为“手动填写版”，而不是由 AI 自动操控飞书提交。执行顺序：

1. 用 `lark-cli api` 查询日报规则，确认规则名称、规则 ID、字段名称和必选项。
2. 用 `lark-cli api` 查询当天本人已提交日报，避免重复提交。
3. 输出按飞书日报/周报字段拆分的可复制文本，字段名必须清楚，方便用户逐项粘贴。
4. 输出“小红书运营必做事项”等选项的勾选提示；选项必须来自运行时读取、界面可见项或用户明确确认，不得凭记忆臆造。
5. 输出提交前手动检查清单，提醒用户核对字段、必选项、OKR 关联和附件/图片等界面专属内容。
6. 用户手动提交后，如用户要求，可用 `report/v1/tasks/query` 回读本人日报/周报，核对提交人、规则、提交时间和各字段内容。

不得声称 AI 已提交日报/周报正文，除非用户明确说明自己已在飞书中提交且回读校验成功。保留已成功的任务勾选、明日/下周任务创建和复盘 Base 结果；汇报正文状态应标注为“已生成手动填写稿 / 等待用户手动提交 / 用户已手动提交 / 已回读校验”之一。

## 运行时读取

每次执行重新发现：

- 当前飞书用户。
- 当前有效 OKR 周期、目标、KR、进度和期限。
- 当前 OKR 截止日期、剩余工作日、每个 KR 的当前值、目标值、剩余缺口和可量化指标；无法直接读取指标时，记录不可量化原因并用里程碑判断。
- 可比较的历史 OKR/KR 记录：上一份日报/周报中的 OKR 判断、近期 OKR 进展记录或任务中记录的目标口径，用于识别 OKR 变更。
- 当前 OKR 周期累计风险所需数据：周期剩余工作日、最大 KR 累计缺口、当前速度和最低日均推进要求。
- 未完成、逾期、今日到期、明日到期、今日完成及无日期但与 OKR 相关的任务。
- 昨日已提交日报，重点读取“明日计划”。
- 最近一份有效周报，重点读取“下周计划”，作为本周周报计划，用于日报核对。
- 上周已提交周报，重点读取“下周计划”、问题与风险、需协助 / 需决策事项、方法沉淀和未完成承诺，用于周报连续性核验。
- 本周全部已提交日报，重点读取每日目标、完成、问题风险、经验复盘和明日计划，用于周报复盘。
- 本周日报中的周中预警、数据可信度标注和保 OKR 动作，用于周报复盘。
- 最近日报、周报和任务中的重复执行偏差，用于形成个人重复偏差画像。
- 今日日报任务、规则、字段和必选项。
- 复盘多维表格当前字段与错误类型选项。

不得硬编码个人开放标识、个人 OKR、任务标识或日报实例标识。

## 总 OKR 风险预估

进入日报复盘后，必须先读取 OKR 数据并生成总 OKR 风险预估，再继续读取或追问今日执行细节。

风险预估的数据流：

1. 当前用户身份 -> 当前 OKR 周期。
2. OKR 周期 -> Objective、全部 KR、截止日期、权重、进度或指标。
3. KR 进度和截止日期 -> 剩余缺口、剩余工作日、最低日均推进要求。
4. 今日任务和昨日计划 -> 判断最大 KR 缺口是否已被今日或明日任务承接。
5. 最近日报/周报中的 OKR 判断 -> 当前 OKR 数据，识别 OKR/KR 变更或口径冲突。
6. 每条关键判断 -> 数据来源与可信度。

风险预估输出至少包含：

- 当前 Objective。
- 截止日期和剩余工作日。
- 每个 KR 的当前进度和剩余缺口。
- 最大 KR 缺口。
- 最低日均推进要求。
- 当前达成概率：高 / 中 / 低。
- 数据来源与可信度。
- 本周期累计风险和明日计划对达成概率的影响。
- 明天必须优先承接的 1-3 个保 OKR 动作。

如果 OKR 进度接口没有返回可量化当前值，不得编造进度；用已读取 KR 文本、用户确认事实和任务完成情况做“里程碑风险判断”，并标注“指标缺失，需人工确认当前值”。

如果历史记录与当前 OKR 数据不一致，不得直接覆盖旧判断；先输出 OKR 变更记录或“疑似 OKR 变更，待确认”。如果无法读取历史快照，标注“无法系统确认 OKR 是否变更”，并把判断可信度降为中或低。

## 飞书任务比对

获取今日计划时，同时读取：

- 上一工作日日报的“明日计划”。
- 最近一份有效周报的“下周计划”，作为本周周报计划。
- 今日飞书任务：未完成、今日到期、逾期、已完成且与今日有关、无日期但与 OKR/KR 相关。

比对结果必须展示给用户确认：

- 两边都有：作为今日核心计划。
- 日报计划有、飞书任务无：询问是否补建任务，或记录不创建任务原因。
- 飞书任务有、日报计划无：标记为额外承诺，追问来源、OKR 关系和是否挤占核心计划。
- 周报计划有、日报计划和飞书任务都无：标记为周计划断链，询问是否补建任务、放入明日计划、本周后续任务、协助事项或取消。
- 日报计划或飞书任务与周报计划冲突：先确认优先级和取舍，不自动覆盖。
- 飞书任务逾期或未完成：进入根因追问和补救方案商讨。
- 飞书任务已由用户确认完成：进入今日任务勾选完成预览，确认后才可调用 `lark-cli task +complete`。

推荐命令：

```powershell
lark-cli task +get-my-tasks --help
lark-cli task +search --help
lark-cli task +create --help
lark-cli task +update --help
```

实际调用前先查看对应 schema 或命令帮助，不猜测参数结构。

## 今日任务勾选完成

日报闭环写入前必须展示今日任务勾选完成预览。将勾选完成的任务必须来自今日飞书任务，并且由用户确认已完成。

预览至少包含：

- 任务标题。
- 任务链接或 guid。
- 完成依据。
- 对应日报字段或今日完成事项。
- 将调用的动作：`lark-cli task +complete`。

不得勾选完成以下任务：

- 部分完成、受阻、顺延或等待数据的任务。
- 仍需进入明日计划继续承接的任务。
- 用户没有明确确认完成的任务。
- 只完成了前置动作但未满足任务验收标准的任务。

执行前必须读取 `lark-cli task +complete --help`，确认参数格式。执行后必须回读任务，核对任务已完成。部分任务勾选失败时，保留已成功结果，列出失败任务和原因，重试前再次展示预览。

## 明日计划任务化

明日计划核心执行项必须创建或更新飞书任务。纯复盘、风险观察、原则判断或暂无法定义下一动作的条目可以不创建任务，但必须展示不任务化原因。

任务预览至少包含：

- 任务标题。
- 对应目标/KR。
- 截止日期，通常是下一工作日。
- 优先级。
- 验收标准。
- 来源日报日期。
- 创建新任务或更新已有任务。

由未完成计划产生的补救动作默认必须创建或更新任务。创建或更新飞书任务前必须展示任务预览并取得用户确认；不得把用户未确认的明日计划写入任务系统。

## 下周计划任务化

周报中的下周核心执行项必须创建或更新飞书任务。由本周未完成、受阻或高风险事项产生的纠偏动作默认必须任务化。

任务预览至少包含：

- 任务标题。
- 对应目标/KR。
- 截止日期。
- 优先级。
- 验收标准。
- 来源周报日期。
- 创建新任务或更新已有任务。

纯复盘、方法原则、风险观察或暂无法定义下一动作的条目可以不创建任务，但必须展示不任务化原因。创建或更新飞书任务前必须展示任务预览并取得用户确认。

## 参数流

最小数据流：

1. 当前用户身份 -> OKR 周期、任务筛选、日报提交人、Base `人员` 字段。
2. OKR 周期 ID -> 目标、KR、进度、截止时间、剩余工作日和最大缺口。
3. 上一工作日日报 -> 今日计划核查清单。
4. 最近一份有效周报 -> 本周周报计划核查清单。
5. 今日飞书任务 -> 与昨日“明日计划”和本周周报计划比对，生成今日核查清单。
6. 上周周报 -> 本周承诺核验基线。
7. 本周全部日报 -> 周报执行事实证据链。
8. 今日日报/周报规则 ID 和字段 -> 草稿字段和必选项。
9. 今日已确认完成任务 -> 飞书任务勾选完成预览。
10. 明日计划或下周计划核心执行项 -> 飞书任务创建或更新预览。
11. Base token、table ID、field IDs -> 复盘待写入内容预览、重复查询、创建和回读。
12. 创建成功的 record IDs、创建或更新的任务 IDs、勾选完成的任务 IDs -> 写入校验。

补充数据流：

- 历史 OKR/KR 判断 + 当前 OKR/KR 数据 -> OKR 变更记录。
- 飞书 OKR / 飞书任务 / 日报周报 / Base / 用户口述 / AI 推断 -> 数据来源与可信度。
- 本周周报计划 + 今日计划 + 今日任务 + KR 速度 + 达成概率 -> 周中预警判断。
- 明日计划 / 下周计划 + KR 剩余缺口 + 最低推进要求 -> 计划质量和达成概率影响判断。
- 最近日报 / 周报 / 任务中的同类偏差 -> 个人重复偏差画像。

## 连续性检查

将昨日“明日计划”解析成今日核查清单。每项必须有最终状态；部分完成、受阻及仍有效的未完成项必须进入新“明日计划”，或明确取消原因。

同时读取飞书任务用于补漏和判断风险，但不能让任务列表无声覆盖昨日计划。

日报连续性检查还必须读取最近一份有效周报的“下周计划”，作为本周周报计划。将本周周报计划与昨日“明日计划”、今日飞书任务和今日执行事实比对；周报计划核心项未被承接时，必须标记为周计划断链并形成去向。

日报连续性检查还必须检查是否触发周中预警：周计划断链、重点 KR 停滞、达成概率下降、重复延期或最大 KR 缺口无人承接。触发后必须进入明日计划、本周后续任务、协助事项或风险升级。

日报连续性检查还必须判断明日计划可执行性：产能、依赖、验收标准、KR 贡献、是否覆盖最低推进要求，以及是否能提升 OKR 达成概率。计划不足时必须回到明日计划重排。

周报连续性检查必须读取上周周报和本周全部日报。将上周周报“下周计划”解析成本周承诺核查清单，每项必须有最终状态；本周全部日报用于证明每日执行事实、计划变化和风险变化。不能让本周任务列表或临时总结覆盖上周周报承诺。

周报连续性检查还必须汇总本周 OKR/KR 变更记录、关键判断数据可信度和本周日报中的周中预警。未纠偏的预警必须进入下周计划、需协助事项或风险升级。

周报连续性检查还必须判断下周计划对 OKR 达成概率的影响，并识别个人重复偏差画像。若下周计划不能提升或维持达成概率，必须补充加速、降范围、加资源、换方法、升级或目标调整建议。

## 提交安全

- 起草前读取日报规范。
- 提交前展示完整字段、必选项和手动填写映射。
- 用户修改后重新检查规范并再次确认。
- 不自动提交日报/周报正文；用户明确确认后，只能执行任务、Base 等结构化写入。
- 日报/周报正文固定交付手动填写稿；开放 API 只用于规则/历史查询和用户手动提交后的可选校验。
- 今日任务勾选完成、明日任务创建或更新、复盘 Base 写入都必须在同一份写入预览中展示；用户明确确认后才能执行。
- 不得删除飞书任务。不得将未完成、受阻、顺延或仍需承接的任务勾选完成。

## 校验

用户手动提交后，如用户要求，查询日报历史，核对：

- 提交人。
- 日期和提交时间。
- 日报规则。
- 各字段内容。
- 必选项状态。

若用户手动提交日报成功但多维表格同步失败，保留已提交日报，列出失败记录和原因。不得为了追求“全成功”而静默重复提交日报。

创建或更新飞书任务后，必须回读任务并核对标题、截止日期、负责人、验收标准和来源日报日期。勾选完成飞书任务后，必须回读任务并核对完成状态。任务写入或勾选完成部分失败时，保留已成功任务，列出失败任务，重试前再次预览确认。

## 失败分类

- 认证失败：切换到 `lark-shared` 重新登录或确认身份。
- 权限不足：说明缺少资源和影响，不继续写入。
- 资源不存在：检查 `team-config.md` 是否被复制到其他团队后未更新。
- 结构漂移：字段名称、ID 或类型不一致，停止写入并要求更新配置。
- 短暂读取失败：可重试；仍失败则进入“部分数据未读取”草稿。
- 手动填写未完成：不声称日报已提交；可继续输出字段稿和检查清单。
- 校验不一致：保留系统返回信息，提示人工复核，不做覆盖修复。
